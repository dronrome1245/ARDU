# AGENTS.md

## Назначение

Этот репозиторий — единый источник правды по проекту ARDU: потолочная лампа со светомузыкой, микрофоном, будильником-рассветом и управлением со смартфона.

Агент должен помогать проектировать, писать и проверять прошивки Arduino Nano и ESP8266, протокол управления, приложение и документацию, не теряя уже принятые аппаратные ограничения.

## Обязательный порядок чтения

Перед изменениями читать:

1. `00_НАЧАТЬ_ЗДЕСЬ.md`
2. `01_СТАТУС_ПРОЕКТА.md`
3. `02_СЛЕДУЮЩИЙ_ШАГ.md`
4. `03_СОСТОЯНИЕ_ПРОЕКТА.yaml`
5. относящиеся к задаче файлы из `01_Контур_продукта/`, `02_Архитектура_и_решения/` и `05_Коллизии/`.

## Фактическая база

Не считать подтвержденным то, чего нет в репозитории или в явном сообщении владельца проекта.

Подтверждено:

- есть Arduino Nano;
- есть модуль с маркировкой `ESP8266MOD`, `AI-THINKER`;
- целевой источник звука — микрофон внутри потолочной лампы;
- используется MAX9814;
- используется адресная лента WS2812B;
- в предыдущей версии проекта использовались HC-05, DS3231 и мобильное управление;
- целевой интерфейс управления — Wi‑Fi через приложение;
- новые аппаратные покупки нежелательны;
- проект AlexGyver ColorMusic можно использовать как техническую базу с соблюдением его MIT License.

## Политика изменений

Агент может автономно изменять:

- документацию;
- тестовые скетчи;
- прошивку в отдельных ветках/коммитах, если назначение и пины уже подтверждены;
- код приложения, если сетевой протокол уже зафиксирован;
- тесты и служебные скрипты.

Требуют подтверждения владельца до фиксации как окончательного решения:

- изменение электрической схемы питания;
- подача 5 В на цепь, рассчитанную только на 3.3 В;
- изменение фактической распиновки собранного макета;
- отказ от Arduino Nano как основного контроллера;
- отказ от Wi‑Fi в пользу Bluetooth как конечного интерфейса;
- изменение формата команд, ломающее совместимость с приложением;
- выбор лицензии для собственного кода ARDU.

## Запреты

- Не создавать фиктивные значения, заглушки и псевдоданные.
- Не писать в рабочие файлы `[TODO]`, `[XXX]`, `[вставить]` и подобные маркеры.
- Не считать старую распиновку окончательной, если в источниках есть конфликт.
- Не подключать ESP8266 напрямую к 5-вольтовой логике без проверки допустимых уровней и схемы конкретной платы.
- Не копировать крупные фрагменты стороннего кода без фиксации источника и лицензии.
- Не удалять рабочий функционал ColorMusic только ради упрощения переноса.

## Архитектурное правило текущей фазы

Рабочая базовая схема:

`мобильное приложение → Wi‑Fi → ESP8266 → UART → Arduino Nano → MAX9814 / DS3231 / WS2812B`

HC-05 допускается как временный резерв при отладке, но не является целевым каналом управления.

После завершения любой законченной задачи синхронно обновить:

## Правила кода

- Избегать блокирующих `delay()` в основной рабочей логике, если это мешает связи, RTC или анимации.
- Для Arduino Nano учитывать ограничения ATmega328P по SRAM и Flash.
- Для команд использовать ограниченные буферы и детерминированный разбор; избегать бесконтрольного роста `String` на Nano.
- Разделять транспорт команд и бизнес-логику: одна и та же команда должна иметь одинаковый смысл при Bluetooth и Wi‑Fi.
- Пины, размеры буферов, количество LED и электрические ограничения держать в одном конфигурационном месте прошивки.
- Любую миграцию алгоритмов из AVR-кода на ESP8266 проверять отдельно; AVR-специфичный доступ к АЦП и FHT не считать переносимым автоматически.

## Верификация

До появления полноценного CI минимальная проверка для изменения прошивки:

1. компиляция целевой платы в Arduino IDE или Arduino CLI;
2. отсутствие ошибок библиотек и превышения памяти;
3. тест Serial/UART без ленты;
4. тест одного/малого числа LED с ограниченной яркостью;
5. тест микрофона и калибровки;
6. только затем совместный тест Wi‑Fi + аудио + лента.

Для изменений протокола обязательно сверять `06_Интерфейс_управления/ПРОТОКОЛ_КОМАНД.md`.
