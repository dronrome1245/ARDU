# Протокол управления ARDU

Версия документа: 0.2  
Дата: 2026-09-06

## 1. Статус документа

После разбора `Ardublock2.aia` выяснилось, что ранее записанные команды вида `L1`, `M1`, `MM:2`, `MP1:...` **не являются фактическим протоколом старого приложения LumpV3.1**. Это была проектная идея нового компактного протокола.

Так как новое приложение пишется заново, старый Bluetooth-протокол не требуется сохранять как внешний контракт.

Целевая схема разделяется на два уровня:

1. **телефон ↔ ESP8266** — новый локальный HTTP API;
2. **ESP8266 ↔ Nano** — компактный внутренний UART-протокол, который окончательно фиксируется вместе с моделью прошивки.

---

## 2. Фактически подтверждённый старый протокол LumpV3.1

### Disco

Из `Disco.bky` подтверждены:

| Команда | Старый смысл |
|---|---|
| `!` | запрос настроек светомузыки |
| `0` | калибровка шума |
| `1`…`9` | выбор одного из 9 режимов |
| `$A,B` | яркость активных/фоновых LED, значения 0–255 |
| `<` | параметр №1 уменьшить |
| `>` | параметр №1 увеличить |
| `+` | параметр №2 увеличить |
| `-` | параметр №2 уменьшить |
| `#` | сменить подрежим |

### Obichniy

Из `Obichniy.bky` подтверждены:

| Команда | Старый смысл |
|---|---|
| `%` | запрос параметров обычного режима/будильника |
| `1` | будильник ВКЛ |
| `0` | будильник ВЫКЛ |
| `?K,B,T` | температура, максимальная яркость, длительность рассвета |
| `@H,M` | время будильника |
| `2` | запрос времени |
| `5H,M` | ручная установка времени |
| `3` | старое включение люстр |
| `4` | старое выключение люстр |

Команды `3/4` в ARDU больше не нужны: штатный белый свет двух круглых корпусов не используется.

### Nochnik и FON

В загруженном `.aia` полноценный обмен настройками этих экранов не подтверждён. Нельзя придумывать старые команды для них.

## 3. Новый внешний API: телефон ↔ ESP8266

Внешний интерфейс v1 — локальный HTTP API.

Предварительные маршруты:

- `GET /api/status`
- `GET /api/settings`
- `GET /api/time`
- `POST /api/power`
- `POST /api/mode`
- `POST /api/music/mode`
- `POST /api/music/settings`
- `POST /api/music/calibrate`
- `POST /api/ambient/effect`
- `POST /api/ambient/settings`
- `POST /api/night/settings`
- `POST /api/alarm/settings`
- `POST /api/alarm/stop-dawn`
- `POST /api/time/sync`

JSON-поля не объявлять окончательными до фиксации структуры настроек Nano.

Подробно: `05_WiFi_и_приложение/ФУНКЦИОНАЛЬНАЯ_МОДЕЛЬ.md`.

## 4. Внутренний UART: ESP8266 ↔ Nano

Требования:

- текстовый протокол для простоты отладки;
- каждая команда заканчивается `\n`;
- Nano отвечает `OK`, данными или кодом ошибки;
- ESP не должен подтверждать HTTP-запрос как успешный, пока Nano не подтвердил применение критической команды;
- фиксированный входной буфер;
- игнорировать `\r`;
- неизвестная/ошибочная команда не меняет состояние;
- все числовые параметры проверяются по диапазону.

До реализации допустим диагностический тест:

- `PING\n`
- `PONG\n`

Окончательные команды UART будут сформированы из ID и параметров документа `04_Прошивка/РЕЖИМЫ_РАБОТЫ.md`, а не из старых символов App Inventor.

## 5. Миграционное правило

Старый протокол LumpV3.1 хранится как исторический источник поведения. Его можно временно поддержать на Nano во время переноса ColorMusic, если это ускоряет тестирование, но новая система не обязана сохранять совместимость со старым приложением.


## 5. Текущий тестовый UART фонового контроллера (2026-09-26)

Это **не окончательная заморозка всего Nano↔ESP протокола**, а фактический интерфейс `nano_ambient_r1` для аппаратной проверки:

- `EFFECT F01|F02|F03` — явный выбор фонового эффекта;
- `NEXT`, `PREV` — циклическая навигация;
- `AUTO ON|OFF` — автоперебор;
- `PERIOD <1..255>` — период автоперебора в секундах;
- `BRIGHT <0..255>`;
- `HUE <0..255>`, `SAT <0..255>`, `SPEED ...` — параметры текущего эффекта;
- `STEP10 <5..100>` — spatial rainbow step ×10 для F03;
- `STATUS`, `PING`, `ON`, `OFF`, `HELP`.

После аппаратного pass этого слоя команды можно использовать как основу внутреннего ESP↔Nano протокола.


## 6. Текущий тестовый UART ALARM R1 (2026-09-26)

Не является окончательной заморозкой полного Nano↔ESP протокола.

- `TIME` — прочитать RTC;
- `SET YYYY-MM-DD HH:MM:SS` — установить RTC;
- `ALARMSET HH:MM` — установить ежедневное время будильника;
- `ALARM ON` / `ALARM OFF` — включить/выключить;
- `ALARM CLEARLAST` — очистить дату последнего trigger для повторного теста;
- `STATUS` — RTC validity, alarm state, persisted state;
- асинхронное событие: `EVENT ALARM_TRIGGER RTC=...`.

ALARM R1 не включает LED dawn; это следующий слой после подтверждения trigger/persistence.


## 7. Текущий тестовый UART DAWN R1 (2026-09-26)

DAWN R1 расширяет ALARM R1:

- `FADEMIN <1..120>`
- `MAXBR <1..255>`
- `STARTHUE <0..255>`
- `ENDHUE <0..255>`
- `DAWN TEST <5..120>` — ускоренный диагностический запуск в секундах;
- `DAWN START` — ручной запуск с реальным `FADEMIN`;
- `DAWN STOP` — немедленная остановка/гашение;
- alarm trigger автоматически запускает dawn;
- события: `EVENT DAWN_START ...`, `EVENT DAWN_COMPLETE`, `EVENT DAWN_STOP`.

Внешний HTTP API по-прежнему использует семантические поля `fade_minutes/max_brightness/start_hue/end_hue`; команда `DAWN TEST` остаётся сервисной.


## 8. DAWN R2 runtime/recovery diagnostics (2026-09-26)

Команды пользователя остаются как в DAWN R1. Добавлена диагностика состояния:

- STATUS: `SOURCE=<ALARM|MANUAL|TEST|NONE>`, `RUNTIME_SAVED=YES|NO`, `RECOVERED=YES|NO`;
- после reset активного рассвета: `EVENT DAWN_RECOVER PHASE=RUNNING ...`;
- после reset сохранённого HOLD: `EVENT DAWN_RECOVER PHASE=HOLD ...`;
- при небезопасном восстановлении из-за RTC/state: `EVENT DAWN_RECOVER_ABORT REASON=...`.

Recovery не требует команды ESP/приложения и выполняется автономно Nano+DS3231.


## 9. Текущий тестовый UART NIGHT R1 (2026-09-26)

NIGHT R1 использует:

- `ON` / `OFF`;
- `HUE <0..255>`;
- `SAT <0..255>`;
- `BRIGHT <0..255>`;
- `DEFAULTS`;
- `STATUS`, `PING`, `HELP`.

STATUS: `FW=NIGHT REV=1 MODE=NIGHT POWER=... HUE=... SAT=... BRIGHTNESS=... SAVED=...`.

Изменение параметров сразу сохраняется во внутренней EEPROM. Расписание ночника в R1 отсутствует.


## 10. Текущий тестовый UART NIGHT R2 schedule (2026-09-26)

NIGHT R2 сохраняет команды R1 и добавляет:

- `TIME`;
- `SCHEDULESET HH:MM HH:MM` — время ON и OFF;
- `SCHEDULE ON`;
- `SCHEDULE OFF`.

STATUS дополнительно:
- `CONTROL=MANUAL|SCHEDULE`;
- `MANUAL_POWER=ON|OFF`;
- `SCHEDULE=ON|OFF`;
- `SCHED_ON=HH:MM`;
- `SCHED_OFF=HH:MM`;
- `WINDOW=ACTIVE|INACTIVE`;
- `RTC_PRESENT`, `RTC_VALID`, `TIME`.

Асинхронный переход расписания: `EVENT NIGHT_SCHEDULE POWER=ON|OFF`.

Manual `ON/OFF` является явным override и отключает schedule.
