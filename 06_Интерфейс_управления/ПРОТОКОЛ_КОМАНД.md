# Протокол команд ARDU

Версия документа: 0.1

## 1. Принцип

Команды не зависят от транспорта.

Одинаковая строка должна иметь одинаковый смысл при передаче через:

- HC-05;
- ESP8266/Wi‑Fi;
- USB Serial в тестовом режиме.

Каждая команда завершается `\n`.

## 2. Существующие короткие команды

| Команда | Смысл |
|---|---|
| `L1` | Обычный свет ВКЛ |
| `L0` | Обычный свет ВЫКЛ |
| `N1` | Ночник ВКЛ |
| `N0` | Ночник ВЫКЛ |
| `M1` | Светомузыка ВКЛ |
| `M0` | Светомузыка ВЫКЛ |
| `E1` | Эффекты ВКЛ |
| `E0` | Эффекты ВЫКЛ |
| `A1` | Будильник ВКЛ |
| `A0` | Будильник ВЫКЛ |
| `T:<value>` | Цветовая температура обычного света |
| `B:<value>` | Яркость обычного света |
| `NK:<value>` | Цветовая температура ночника |
| `NB:<value>` | Яркость ночника |
| `DA1` | Автосмена эффектов ВКЛ |
| `DA0` | Автосмена эффектов ВЫКЛ |
| `DE:<index>` | Выбрать эффект |
| `MBA:<value>` | Яркость активных LED светомузыки |
| `MBB:<value>` | Яркость фоновых LED светомузыки |
| `CAL` | Калибровка шума |
| `MM:<index>` | Режим светомузыки |
| `MP1:<value>` | Параметр 1 текущего режима |
| `MP2:<value>` | Параметр 2 текущего режима |
| `AT:<h>,<m>` | Время будильника |
| `AF:<value>` | Длительность рассвета |
| `GT` | Запросить время с Arduino |
| `ST:<h>,<m>,<s>` | Синхронизировать время RTC |

## 4. Параметры режимов светомузыки

Принятые индексы:

| Index | Режим | MP1 | MP2 |
|---:|---|---|---|
| 0 | VU градиент | плавность | не используется |
| 1 | VU радуга | плавность | скорость радуги |
| 2 | 5 полос | плавность | чувствительность |
| 3 | 3 полосы | плавность | чувствительность |
| 4 | доминирующая частота | плавность | чувствительность |
| 5 | стробоскоп | плавность | период/частота |
| 6 | постоянный цвет | HUE | насыщенность |
| 7 | плавная смена цвета | скорость | насыщенность |
| 8 | бегущая радуга | скорость | шаг радуги |
| 9 | анализатор спектра | шаг цвета | начальный HUE |

## 5. Ответы устройства

Из старого контракта подтвержден ответ на `GT`:

`TIME_IS <H>:<M>:<S>\n`

Для калибровки в накопленных материалах использовались статусы вида:

- `STATUS:CALIBRATING_NOISE`
- `STATUS:CALIBRATION_DONE:<level>`

Эти строки допускаются как диагностические ответы, пока приложение не потребует другой формат.

## 6. Диагностическая команда шлюза

Для стендовой проверки Wi‑Fi/UART вводится внутренняя диагностическая пара:

- запрос: `PING\n`
- ответ: `PONG\n`

Она не обязана отображаться в пользовательском интерфейсе приложения.

## 7. STOP_ALARM_DAWN

В длинном протоколе была команда `STOP_ALARM_DAWN`, но в предоставленной таблице коротких команд для нее нет зафиксированного сокращения.

До отдельного решения Nano должен принимать полную строку `STOP_ALARM_DAWN\n`; короткий алиас не вводится самовольно.

## 8. Правила парсера

- Игнорировать `\r`.
- Команду обрабатывать только после `\n`.
- Ограничивать длину входной строки фиксированным буфером.
- Не выполнять частично принятую команду.
- Не зависать на неизвестной команде.
- Не менять текущий режим при ошибке параметра.
- Для числовых параметров проверять допустимый диапазон до применения.

## 9. Миграция Bluetooth → Wi‑Fi

ESP8266 должен передавать эти строки Nano без преобразования смысла. Мобильное приложение меняет способ подключения, но не бизнес-команды.
