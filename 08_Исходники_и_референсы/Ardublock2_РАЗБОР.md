# Разбор старого приложения Ardublock2.aia

Дата анализа: 2026-09-06  
Исходник: `Ardublock2.aia`  
Внутреннее имя проекта: `LumpV3.1`

## 1. Состав проекта

В `.aia` обнаружены пять экранов:

- `Screen1` — главное меню и Bluetooth;
- `Obichniy` — часы, будильник, рассвет и старое управление люстрами;
- `Nochnik` — настройки ночника;
- `FON` — фоновые эффекты;
- `Disco` — светомузыка.

Для каждого экрана присутствуют файлы Designer (`.scm`) и Blocks (`.bky`).

## 2. Screen1

Главное меню содержит четыре функциональных раздела:

- Обычный режим;
- Ночник;
- Фоновые эффекты;
- Дискотека.

Bluetooth реализован через `BluetoothClient` и `TinyDB`; приложение сохраняло выбранный адрес/клиент и пыталось повторно подключаться на дочерних экранах.

Для новой Wi‑Fi версии эту схему соединения не переносить.

## 3. Disco — подтверждённые режимы

В блоках процедуры `rezhim` найдены 9 режимов:

1. `Шкала громкости (градиент)`;
2. `Шкала громкости (радуга)`;
3. `Цветомузыка (5 полос)`;
4. `Цветомузыка (3 полосы)`;
5. `Цветомузыка (1 полоса)`;
6. `Стробоскоп`;
7. `Цветная подсветка`;
8. `Бегущие частоты`;
9. `Анализатор спектра`.

Это совпадает с опубликованной таблицей управления ColorMusic v2.x.

### Подрежимы

В процедуре `podrezhim` присутствуют:

- `3 частоты`;
- `Низкие`;
- `Средние`;
- `Высокие`;
- `Постоянный`;
- `Плавная смена цвета`;
- `Бегущая радуга`.

### Названия параметров

В процедуре `strelki` найдены подписи:

- `Плавность анимации`;
- `Цвет`;
- `Скорость`;
- `Шаг цвета`;
- `Плавность вспышек`;
- `Скорость радуги`;
- `Частота вспышек`;
- `Чувствительность`;
- `Насыщенность`;
- `Шаг радуги`;
- для неприменимых параметров использовалась подпись `НЕ рабочие в этом режиме`.

### Общие настройки яркости

На экране есть два бегунка 0–100 %:

- `Яркость горящих светодиодов` — по умолчанию 50 %;
- `Яркость НЕ горящих светодиодов` — по умолчанию 10 %.

При отправке значения переводились из процентов в диапазон 0–255.

### Фактические старые команды Disco

Из блоков подтверждены:

- `!` — запрос настроек;
- `0` — калибровка шума;
- `1`…`9` — выбор режима;
- `$<active>,<background>` — общая яркость активных и фоновых LED;
- `<` / `>` — изменение параметра №1;
- `+` / `-` — изменение параметра №2;
- `#` — переключение подрежима.

Старый протокол фиксируется только как история и не является контрактом нового Wi‑Fi API.

## 4. Obichniy — подтверждённые функции

На экране присутствуют:

- текущее время;
- синхронизация/установка времени Arduino/RTC;
- будильник ВКЛ/ВЫКЛ;
- время будильника;
- температура света в диапазоне 1800–6600 K;
- максимальная яркость;
- длительность рассвета;
- старые кнопки ВКЛ/ОТКЛ люстр.

Фактические команды в блоках:

- `%` — запрос параметров экрана;
- `1` / `0` — будильник ВКЛ/ВЫКЛ;
- `?K,B,T` — температура/яркость/длительность рассвета;
- `@H,M` — время будильника;
- `2` — запрос времени;
- `5H,M` — ручная установка времени;
- `3` / `4` — старое включение/выключение люстр.

В новой ARDU функции `3/4` удалить, потому что штатный белый свет круглых корпусов не используется.

## 5. Nochnik

Designer подтверждает планировавшиеся параметры:

- переключатель `НОЧНИК`;
- час перехода на ночную подсветку: варианты `20,21,22,23,0`;
- час перехода на дневную подсветку: варианты `6,7,8,9`;
- температура 1800–6600 K;
- яркость 0–100 %;
- кнопка `Применить`.

Но Blocks этого экрана содержат в основном только Bluetooth-подключение/статус. Полноценная отправка настроек ночника в загруженном `.aia` не подтверждена.

Следовательно, старый экран рассматривается как функциональный замысел, а не завершённый контракт.

## 6. FON

Designer содержит:

- переключатель `Автоперебор эффектов`;
- `Следующий эффект`;
- `Предыдущий эффект`.

Blocks содержат в основном Bluetooth-подключение/статус. Управление эффектами в загруженной версии не завершено.

Конкретные фоновые эффекты для новой версии поэтому берутся из подтверждённых подрежимов ColorMusic: постоянный цвет, плавная смена цвета, бегущая радуга.

## 7. Что полезно перенести

Переносим функциональный смысл:

- разделение на Светомузыку / Фон / Ночник / Будильник;
- девять исходных ColorMusic-режимов;
- подрежимы частот;
- два уровня яркости музыкального режима;
- калибровку шума;
- расписание/параметры рассвета;
- автоперебор фоновых эффектов.

Не переносим:

- Bluetooth-навигацию и переподключение на каждом экране;
- старый внешний протокол символов как обязательный API;
- управление штатными люстрами;
- буквальную CCT/Kelvin-модель для WS2812B.
