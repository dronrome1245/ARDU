# ARDU — M02 R1 VU rainbow hardware test

Дата: 2026-09-27

## Scope

M02 R1 переносит второй VU-режим ColorMusic v2.10 на уже подтверждённый ARDU audio frontend:

- MAX9814 Out -> Nano A0 напрямую;
- Gain -> Vdd = 40 dB;
- AR floating;
- ADC reference = DEFAULT;
- одно кольцо 43 WS2812B на D6;
- D7 остаётся LOW и второе кольцо пока не подключается;
- background по умолчанию = 0;
- геометрия VU та же, что у уже пройденного M01;
- активная шкала окрашена вращающейся Rainbow palette;
- используется прошедший в M05 R4 baseline FastLED/UART: `FASTLED_ALLOW_INTERRUPTS=1` + 5 ms RX guard.

M02 R1 не меняет wiring и не вводит новую FHT-логику.

## 1. Verify + Upload

Открыть:

`04_Прошивка/nano_m02_r1/nano_m02_r1.ino`

Arduino IDE:

- Board: Arduino Nano;
- Processor: ATmega328P (Old Bootloader);
- Serial Monitor: 115200 baud, Newline.

После старта ожидается:

```
ARDU NANO M02 R1 READY
RUN ADC THEN CAL IN QUIET ROOM BEFORE MUSIC TEST
STATUS FW=M02 REV=1 ...
```

## 2. Frontend gate

Сначала отправить:

```
ADC
STATUS
```

Норма:

- `ADC AVG` в защитном диапазоне 120..400; на текущем исправном стенде обычно около 240..260;
- `MIN` не должен быть около 0;
- `MAX` не должен быть около 1023;
- в STATUS: `DC_OK=YES`.

Если `DC_OK=NO` или AVG вне 120..400 — не продолжать CAL и визуальный тест; сначала восстановить MAX9814/A0.

## 3. Калибровка в тишине

В тихой комнате:

```
CAL
STATUS
```

Ожидается:

```
CAL DC=... QUIET_MAX=... LOW_PASS=...
```

и затем:

- `CAL=YES`;
- `DC_OK=YES`;
- `DC` остаётся 120..400.

Если получено `ERR CAL_BAD_DC`, M02 не засчитывать.

## 4. Базовая визуальная проверка

Установить:

```
BACKGROUND 0
BRIGHT 64
SMOOTH 30
RAINSTEP10 50
ON
```

Включить обычную музыку.

Критерии:

- шкала симметрично расходится от одного центрального LED по обе стороны 43-LED кольца;
- длина шкалы меняется с громкостью;
- активные LED имеют радужную окраску;
- радуга сама медленно смещается во времени;
- в паузе при `BACKGROUND 0` кольцо полностью гаснет.

Для диагностики можно отправлять:

```
AUDIO
```

Поле `PAIRS` должно изменяться вместе с визуальной длиной шкалы.

## 5. Rainbow speed

При продолжающейся музыке:

```
RAINSTEP10 5
```

Радуга должна смещаться заметно медленнее.

Затем:

```
RAINSTEP10 100
```

Смещение должно стать заметно быстрее.

Вернуть:

```
RAINSTEP10 50
```

## 6. Smoothing

Сравнить:

```
SMOOTH 10
```

и:

```
SMOOTH 80
```

Ожидается заметное изменение инерционности VU без зависания или потери реакции.

Вернуть:

```
SMOOTH 30
```

## 7. UART regression при активной ленте

Во время музыки и активной радуги быстро отправить несколько раз:

```
STATUS
AUDIO
STATUS
AUDIO
STATUS
```

Критерий:

- нет `ERR UNKNOWN_COMMAND` из-за повреждения входной строки;
- ответы читаемые;
- визуальный вывод не зависает и не получает заметных артефактов.

## 8. ON/OFF

```
OFF
```

Кольцо должно сразу погаснуть.

Затем:

```
ON
```

M02 снова продолжает работать без reset.

## PASS M02 R1

M02 R1 считается пройденным только если одновременно выполнено:

1. Verify + Upload;
2. startup `FW=M02 REV=1`;
3. валидный A0/DC и успешный CAL;
4. VU реагирует на музыку;
5. Rainbow rendering визуально корректен;
6. `RAINSTEP10` реально меняет скорость;
7. `SMOOTH` реально меняет инерционность;
8. тишина при BACKGROUND=0 полностью гасит кольцо;
9. UART regression при активном FastLED проходит;
10. OFF/ON работает без reset.

После hardware PASS M02 следующий отдельный режим — M06 strobe. Единую прошивку до прохождения M06 не собирать.
