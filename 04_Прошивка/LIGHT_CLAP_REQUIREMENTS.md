# ARDU — обычное освещение и хлопковый выключатель

Дата: 2026-09-27  
Статус: требования до отдельной реализации

## 1. Назначение

ARDU получает отдельный пользовательский режим обычного освещения на WS2812B.

Стабильный ID: `L01`.  
Верхний раздел: `light`.

Отдельные точечные светильники комнаты сохраняются как независимый основной свет, но ARDU больше не ограничивается только декоративными режимами: два WS2812B-кольца также должны уметь работать как обычный свет.

## 2. Базовое поведение L01

Минимальный L01:

- все LED обоих колец показывают одинаковый постоянный свет;
- режим `KELVIN`: приблизительная визуальная температура белого;
- presets: 2700 K / 4000 K / 6000 K;
- произвольный Kelvin в принятом диапазоне;
- режим `RGB`: любой постоянный цвет;
- яркость регулируется;
- включение/выключение доступно из приложения;
- режим не зависит от Wi-Fi после применения команды;
- программный лимит тока обязателен; полный белый не должен обходить лимит питания.

Для WS2812B это RGB-имитация белого, а не настоящий CCT-светодиод. Значение Kelvin является пользовательской приблизительной визуальной настройкой и требует аппаратной/визуальной проверки.

### Startup profile L01

Nano хранит отдельный startup profile обычного света:

- color mode: KELVIN или RGB;
- Kelvin либо custom RGB;
- brightness.

При cold power-on активируется L01 с этим сохранённым profile.

Изменение профиля в приложении должно иметь live preview и отдельный persistent commit, чтобы не писать EEPROM на каждом шаге slider.

## 3. Поведение при подаче 230 В

Требование владельца:

- вторая настенная клавиша по-прежнему полностью подаёт/снимает питание ARDU;
- после холодного старта вследствие появления питания ARDU должен включить обычное освещение `L01`;
- сервисный Reset Nano сам по себе не должен считаться нажатием настенной клавиши.

В общей прошивке различать power-on reset и обычный reset по причине reset ATmega328P, чтобы тестовый/сервисный reset не ломал восстановление состояний.

Конфликт приоритетов `power-on L01` с восстановлением активного DAWN после реального обрыва питания должен быть явно проверен и зафиксирован при сборке общей state machine.

## 4. Хлопковый выключатель

MAX9814 должен использоваться также для хлопкового управления обычным светом.

Обязательное пользовательское поведение:

- хлопковое событие переключает обычное освещение;
- функция не требует телефона, ESP8266 или Интернета;
- после распознавания действие выполняет Nano локально;
- в приложении отображается состояние функции хлопкового выключателя и предусматривается её включение/отключение.

До отдельного hardware test НЕ фиксировать без измерений:

- один хлопок или серия/двойной хлопок;
- окно времени между хлопками;
- амплитудный порог;
- блокировку повторного срабатывания;
- работу распознавания во время музыкальных режимов.

Причина: MAX9814 одновременно является аудиовходом светомузыки; слишком простой single-peak detector может ложно срабатывать на музыку, речь, двери и другие импульсные звуки.

## 5. Отдельный слой до общей прошивки

После hardware pass M02, но до общей Nano-прошивки:

1. реализовать `L01 R1` без хлопков;
2. подтвердить белый свет, яркость, ON/OFF и power/current limit;
3. добавить отдельный clap diagnostic;
4. подобрать распознавание на реальном MAX9814;
5. проверить ложные срабатывания на речь, музыку и бытовые звуки;
6. только после этого объединять clap control с L01;
7. затем собирать полную общую Nano-прошивку.

## 6. Приложение

Экран «Обычный свет»:

- ВКЛ/ВЫКЛ;
- яркость;
- состояние хлопкового выключателя;
- включение/отключение хлопкового выключателя;
- фактическое состояние L01, считанное с Nano.

Developer Mode дополнительно показывает диагностические значения clap detector после его реализации.


## 7. Калибровка clap detector из приложения

Хлопковый detector должен иметь пользовательскую калибровку.

Требования:
- запуск из обычного UI приложения;
- не требовать Developer Mode;
- измерить quiet baseline;
- собрать серию double-clap samples от нескольких пользователей;
- поддержать 3..12 calibration pairs;
- для семьи из трёх пользователей рекомендовать по 3 пары на каждого;
- suggested threshold сначала тестируется без записи EEPROM;
- отдельное подтверждение сохраняет калибровку;
- отмена возвращает последнюю сохранённую;
- приложение показывает progress, ошибки sample и итоговый threshold/sensitivity;
- сохранённая clap calibration переживает полное отключение питания.

Final detector остаётся double-clap на derivative/state-machine принципе AlexGyver/GyverLamp2.
