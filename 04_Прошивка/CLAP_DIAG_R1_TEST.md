# ARDU — CLAP DIAG R1 hardware characterization

Дата: 2026-09-27

## Цель

Этот скетч пока **не включает и не выключает свет**.

Он нужен, чтобы на реальном MAX9814 определить:

- насколько хлопок отличается от тишины;
- насколько хлопок отличается от речи и музыки;
- какое значение P2P пригодно как первый threshold;
- какой естественный интервал получается между двумя хлопками;
- нужен ли в финале один хлопок или двойной хлопок.

Логика final clap switch принимается только после этих измерений.

## 1. Verify + Upload

Открыть:

`04_Прошивка/nano_clap_diag_r1/nano_clap_diag_r1.ino`

Arduino Nano / ATmega328P (Old Bootloader).

Serial Monitor:

- 115200;
- Newline.

Startup:

```
ARDU NANO CLAP DIAG R1 READY
NO LED CONTROL; LOG IMPULSE CANDIDATES ONLY
STATUS FW=CLAP_DIAG REV=1 ...
```

D6/D7 в этом тесте LOW, кольцо не управляется.

## 2. Проверка MAX9814

Отправить:

```
ADC
STATUS
```

Норма:

- ADC AVG примерно в рабочем диапазоне 120..400;
- MIN не около 0;
- MAX не около 1023;
- STATUS: DC_OK=YES.

## 3. Калибровка тишины

В тихой комнате выполнить:

```
CALCLAP
STATUS
```

Ожидается:

```
CALCLAP DC=... QUIET_AVG_P2P=... QUIET_MAX_P2P=... THRESH=...
```

Записать всю строку.

## 4. Одиночные хлопки

Выполнить:

```
CLEAR
ARM ON
```

Сделать 10 обычных хлопков с интервалом примерно 1–2 секунды.

Для распознанного импульса появляется строка вида:

```
EVENT IMPULSE_CANDIDATE MS=... P2P=... PEAK_DEV=... AVG=... GAP_MS=...
```

После 10 хлопков:

```
STATS
```

Нужно оценить:

- сколько EVENTS получилось из 10;
- типичный P2P хлопка;
- MAX_EVENT_P2P.

## 5. Двойные хлопки

```
CLEAR
```

Сделать 5 естественных пар «хлоп-хлоп», не стараясь выдерживать точный интервал.

Смотреть `GAP_MS` второго события в каждой паре.

После:

```
STATS
```

Это нужно для выбора будущего окна double-clap. Пока никакое окно не фиксируется.

## 6. Речь — false positive test

```
CLEAR
```

30 секунд говорить обычным и чуть повышенным голосом рядом с лампой. Не хлопать.

После:

```
STATS
```

Желательно EVENTS=0. Если события есть — сохранить их P2P из лога.

## 7. Музыка — false positive test

```
CLEAR
```

Включить обычную музыку на типичной громкости примерно на 30 секунд.

После:

```
STATS
```

Если EVENTS > 0, записать количество и максимальные P2P кандидатов.

## 8. Бытовые импульсы

```
CLEAR
```

По отдельности проверить несколько звуков:

- стук пальцами/ладонью по столу;
- закрытие двери;
- короткий резкий голосовой звук;
- другой типичный резкий звук в комнате.

После каждого типа можно делать `STATS` и `CLEAR`.

Цель — понять, что ещё пересекает текущий threshold.

## 9. Ручная настройка threshold при необходимости

Если речь/музыка часто дают кандидаты, можно повысить threshold, например:

```
THRESH 250
```

или:

```
THRESH 300
```

После изменения повторить:

- 10 хлопков;
- 30 s речи;
- 30 s музыки.

Нужно найти значение, при котором хлопки всё ещё ловятся стабильно, а ложные события существенно уменьшаются.

## 10. MON для дополнительной диагностики

При необходимости:

```
MON ON
```

Раз в 500 ms будет выводиться текущий P2P/max/threshold/events.

Выключить:

```
MON OFF
```

## Что прислать после теста

Достаточно:

1. строку CALCLAP;
2. STATS после 10 одиночных хлопков;
3. несколько EVENT из двойных хлопков с GAP_MS;
4. STATS после речи;
5. STATS после музыки;
6. какие бытовые звуки дали ложные события;
7. если менялся THRESH — какое значение оказалось лучшим.

По этим данным будет принято отдельное решение о final clap algorithm. Только после этого clap switch будет объединён с L01.
