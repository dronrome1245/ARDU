# ARDU — MAX9814 single-input audio path

Дата: 2026-09-22

## Решение

Для ARDU использовать один подтверждённый аналоговый вход MAX9814 вместо отдельной A2/A3-обвязки ColorMusic.

```text
MAX9814

Vdd  -> Nano 5V
GND  -> Nano GND
Gain -> Vdd       (40 dB)
AR   -> не подключать
Out  -> Nano A0   напрямую
```

Не ставить в этом варианте:
- 100 µF последовательно в сигнальную линию;
- 103/10 nF между двумя ADC-входами;
- внешний AREF-потенциометр;
- pull-down на аудиовход.

ADC reference = DEFAULT (~5 V).

Фактический MAX9814 ранее давал OUT около 1.24–1.25 V и ADC около 250, что безопасно укладывается в DEFAULT AREF.

## Как сохраняются режимы ColorMusic

Один и тот же A0 используется по-разному программно:

- M01/M02: амплитуда/VU по raw ADC;
- M03/M04/M05/M08/M09: 64-sample FHT с программным вычитанием измеренного DC offset.

Визуальная логика режимов, FHT_N=64, группы bins 2..5 / 6..10 / 11..31 и noise gate max+3 сохраняются из поздней ColorMusic. Меняется только аналоговый frontend.

## Почему

Этот тракт уже подтверждён на физическом Nano/MAX9814:
- прямой ADC около 250;
- CALF/noise gate работает;
- 2 kHz -> LOW;
- 5 kHz -> MID;
- 8 kHz -> HIGH;
- M01 VU ранее визуально работал на том же MAX9814/A0.

## Проверочный скетч

`04_Прошивка/nano_audio_single_test/nano_audio_single_test.ino`

Первый тест:
1. STATUS
2. ADC
3. CALV в тишине
4. VU в тишине и при звуке
5. CALF в тишине
6. FREQ в тишине
7. 2/5/8 kHz через FREQ

После этого single-input frontend можно переносить в основную прошивку режимов.
