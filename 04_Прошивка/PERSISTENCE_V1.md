# ARDU — persistence настроек v1

Дата: 2026-09-27  
Статус: обязательное требование общей Nano-прошивки

## 1. Главный принцип

Nano является источником истины по пользовательским настройкам ARDU.

Настройки должны переживать:

- отключение питания второй клавишей 230 В;
- повторное включение питания;
- обычный reset Nano;
- перезапуск ESP8266;
- закрытие/перезапуск мобильного приложения.

Приложение не является единственным местом хранения настроек.

## 2. Что сохраняется на Nano

В общей прошивке сохраняются отдельные настройки каждого режима, даже когда режим сейчас не активен.

Минимально:

- глобальные ограничения/пользовательские параметры;
- L01: color mode (Kelvin/RGB), Kelvin/custom RGB, brightness, clap enabled, calibrated clap derivative threshold и clap sequence timeout;
- M01: brightness/background/smoothing и применимые параметры VU;
- M02: brightness/background/smoothing/rainbow speed;
- M03/M04: brightness/background/smoothing/sensitivity/noise settings;
- M05: brightness/background/submode/smoothing/sensitivity;
- M08: brightness/background/submode/speed/sensitivity;
- M09: brightness/background/HUE_START/HUE_STEP/sensitivity;
- F01/F02/F03 и AMBIENT auto-cycle/period;
- NIGHT R2: hue/saturation/brightness/schedule;
- ALARM/DAWN: enabled/time/fade/max brightness/start/end hue;
- калибровочные пользовательские значения шума MAX9814, если они применимы после аппаратной проверки.

Текущий отдельный `nano_m02_r1` — тестовый скетч и persistence пользовательских параметров не реализует.

## 3. Хранилище Nano

Для v1 использовать внутреннюю EEPROM ATmega328P как основное энергонезависимое хранилище, если итоговая структура после интеграции помещается с безопасным запасом.

Структура должна иметь:

- magic;
- version;
- checksum/CRC;
- значения по умолчанию при невалидной/старой структуре.

AT24C32 на модуле DS3231 не вводить в обязательную архитектуру без необходимости. Перейти на неё можно отдельным решением, если итоговая структура/ресурс внутренней EEPROM окажутся недостаточными.

## 4. Защита EEPROM от износа

Нельзя писать EEPROM на каждом промежуточном положении slider.

Требование к приложению/ESP/Nano:

- изменение slider может применяться к свету в RAM в реальном времени;
- приложение ограничивает частоту live-preview команд;
- окончательное значение после отпускания slider/завершения редактирования должно быть явно сохранено Nano;
- Nano подтверждает persistent save только после успешной записи/проверки;
- использовать `EEPROM.update` либо эквивалент, чтобы не переписывать неизменившиеся байты;
- смена режима/явное завершение редактирования также должна коммитить dirty-настройки.

Из-за мгновенного снятия 230 В нельзя рассчитывать на «записать EEPROM после обнаружения отключения»: питание уже исчезает. Поэтому последнее подтверждённое приложению значение должно быть сохранено ДО отключения питания.

## 5. Стартовое поведение

Сохранение настроек не означает всегда восстановить последний активный режим.

По D-058:

- cold power-on от второй клавиши → активируется L01 с последним сохранённым L01 startup profile (Kelvin/RGB + brightness);
- при этом параметры всех режимов остаются сохранёнными;
- при последующем выборе, например M02, он получает свои последние сохранённые M02-настройки;
- service/reset behavior отдельно отличать от cold power-on и проверять в общей state machine.

## 6. Приложение

Приложение хранит локальный cache настроек всех режимов для удобного UI, но Nano остаётся источником истины.

После подключения приложение:

1. делает `GET /api/settings`;
2. получает полный набор сохранённых настроек всех режимов;
3. обновляет локальный cache;
4. отображает значения Nano.

Это позволяет использовать другой телефон или переустановить приложение без потери настроек лампы.

При изменении параметра:

- UI может показывать live preview;
- финальное значение должно получить подтверждение `persisted=true`/эквивалент от ESP/Nano.

## 7. Критерий общей прошивки

Full regression считается неполным без теста persistence:

1. задать нестандартные параметры минимум в L01, одном Music, Ambient, Night и Alarm;
2. переключить режимы и подтвердить независимость настроек;
3. полностью снять питание;
4. снова подать питание;
5. подтвердить cold power-on→L01;
6. выбрать остальные режимы и проверить восстановление их последних сохранённых параметров;
7. приложение после переподключения должно прочитать те же значения через API.
