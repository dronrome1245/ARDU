# Nano R5 — тёплый рассвет (полная прошивка)

**Единый самостоятельный скетч:** `nano_warm_dawn_v5.ino`, boot `ARDU1 6`. Повторены полные функции Nano R4 (P01..P12 с движением, P11 breathing, F01, Music, L01, Night, RTC, clap и т.д.), заменён **только** старый HSV-рендеринг DAWN, добавлен atom Kelvin opcode78 и перемещено время начала рассвета относительно будильника.

- Warm table L01 `kelvinRgb()`: 1800..4000 K, шаг значения в EEPROM 20 K, начало по умолчанию 2000 K, конец 3600 K.
- `HH:MM` = время завершения рассвета; запускается `fadeMinutes` раньше; при переходе через полночь сохраняет корректный день trigger.
- Яркость от 1/255 до `maxBrightness`, плавный квадратичный рост. После завершения HOLD до STOP или смены режима.
- Dawn EEPROM 16..23 версия **2**, старый v1 HSV рассвет не воспроизводится. Старое время будильника, остальные сохранённые пресеты/кал. данные не стираются. `D 3 3` 10-я позиция 1 означает поддержку; `78 <startStep> <endStep>` – атомарно обе температуры, `77` – SAVE.
- [Arduino Verify PASS](https://github.com/dronrome1245/ARDU/actions/runs/38050231423): 29534/30720 Flash, 1286/2048 globals RAM. Worst-case stack и 44+44 питание только на оборудовании; лимит ≤3000 мА до измерений.

**Физический upload:** Arduino IDE → открыть одноимённый `.ino` → Nano ATmega328P (Old Bootloader), проверенный COM-порт; перед прошивкой временно отсоединить **ESP TX → Nano RX/D0**, не оставлять конфликт UART при USB upload; после успешного Upload вернуть это соединение и проверить `/api/status`. Текущую рабочую полную Nano R4 сохранить как rollback, не загружать HEX из другого проекта.

Сквозная инструкция: `../../RELEASE_WARM_DAWN_DIRECT_ACCEPTANCE.md`.
