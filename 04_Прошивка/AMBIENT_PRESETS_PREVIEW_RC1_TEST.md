Дата: 2026-10-08  
Статус: исходник полной Nano и HEX собраны в CI; физическая загрузка и проверка реального кольца НЕ выполнялись.

## 1. Готовый исходник

- Arduino IDE: `04_Прошивка/nano_ambient_preview_rc1/nano_ambient_preview_rc1.ino`.
- Соседний обязательный файл: `04_Прошивка/nano_ambient_preview_rc1/ambient_preset_probe.h`.
- [Успешная CI Arduino Verify #37809369365](https://github.com/dronrome1245/ARDU/actions/runs/37809369365): default full Nano, preview full Nano, самостоятельный IDE-скетч, host 44-LED tests и синхронизация двух исходников прошли.

**Это не отдельный урезанный тестовый скетч.** В preview входят все текущие Nano v1 подсистемы: L01, Music, Night, Alarm/Dawn/RTC, хлопок, MAX9814/FHT, два зеркальных выхода D6/D7, numeric UART, существующая EEPROM. ESP и Android остаются без изменения.

## 2. Что увидишь на кольце

В старом Android приложении открыть `Фон`, затем вручную выбрать карточку **«Цвет» (F01)**. Это запускает специальную последовательность из четырёх кадровых окон, начиная с первого:

| Время после выбора F01 | Показывается | Начальная яркость |
|---|---|---:|
| ~0–8,2 с | P01 Северное сияние: зелёно-бирюзово-фиолетовые волны | ~45% |
| ~8,2–16,4 с | P04 Космос: тёмный фон, 3 медленно мерцающие звезды | ~25% |
| ~16,4–24,6 с | P05 Камин: живое нерегулярное тёплое мерцание | ~45% |
| ~24,6–32,8 с | Старый F01 — сохранённый постоянный цвет | как сохранено |

Затем цикл повторяется. Нажатие F01 ещё раз или повторный вход в Ambient перезапускает показ. Для полного просмотра требуется 35–40 секунд. Старые F02/F03 сохраняются как отдельные эффекты; их numeric IDs не переиспользованы. В preview-окнах яркость/динамика **ещё не управляются ползунками приложения**. Холодная подача питания по-прежнему запускает L01, а не Ambient.

## 3. Ограничения и решение о загрузке

По [CI #37809369365](https://github.com/dronrome1245/ARDU/actions/runs/37809369365):
- штатная Nano: 28690 / 30720 байт Flash; 1234 / 2048 байт globals SRAM;
- полная preview Nano: **29376 / 30720 байт Flash** и **1234 / 2048 байт globals**;
- запас до аппаратного предела = 1344 байта Flash и 814 байт SRAM под стек/локальные переменные;
- внутренний ориентир ≤29184 байт (95% Flash) превышен на **192 байта**. Это допустимая **проверочная RC для исследования**, не production freeze; реальный worst-case стек и ток ещё не измерены.

**Внимание:** preview собрана из текущей полной Nano v1, включающей ещё не проверенные на устройстве изменения 2026-10-07: `reset-defaults` и исправление `Ambient speed`. При загрузке требуется базовый regression, не только просмотр новых цветов.

## 4. Действия на компьютере

1. `cd C:\ARDU` → `git switch main` → `git pull`.
2. До перепрошивки зафиксируй текущие `GET /api/ping`, `GET /api/status` и `GET /api/settings` (состояние/настройки/текущую версию ESP и Nano).
3. **Сохрани путь возврата:** обычный полный скетч `04_Прошивка/nano_ardu_v1/nano_ardu_v1.ino` доступен в текущем репозитории. Его повторная загрузка возвращает стандартное поведение F01/F02/F03 без preview. Старый ранее прошитый бинарник может отличаться от текущего main; если нужна byte-for-byte копия работающего устройства, полагаться только на исходник из main нельзя.
4. Полностью выключи внешнее питание и USB **перед** перестановкой проводов. Временно отключи **ESP TX0/GPIO1 → Nano D0/RX**; именно эта линия препятствовала предыдущим загрузкам Nano. Делитель `Nano D1/TX → ESP RX` не менять. Nano RESET оставить свободным.
5. **Обеспечь безопасную схему питания для USB Upload**: не подавай одновременно на Nano +5 В от внешнего БП и USB без подтверждённой развязки; не допускай питания обесточенной WS2812B через DATA. Если текущая сборка не позволяет безопасно разъединить питание, сначала проверь конкретную схему и не подключай USB наугад.
6. Arduino IDE → File/Open → `nano_ambient_preview_rc1.ino`. Два файла должны лежать в одном каталоге. Board = **Arduino Nano**, Processor = **ATmega328P (Old Bootloader)**, Port = текущий COM Nano. Нужны FastLED и оригинальная FHT из `04_Прошивка/libraries/FHT`, используемая в прежних Nano-сборках.
7. Нажми **Verify**, ожидается размер около 29376 B Flash / 1234 B globals с теми же версиями библиотек. При неожиданном размере, compile error или ошибке board — **не выполнять Upload**.
8. Если всё соответствует и питание безопасно, выполни **Upload**. Пока ESP TX отключён, в Serial Monitor 115200 / Newline команды `1` → `O 1`, `2` → `D 2 ...`, `4` → `D 4 ...` (RTC, если синхронизирован).
9. Закрой Serial Monitor, полностью выключи питание и USB; восстанови **ESP TX0/GPIO1 → Nano D0/RX**. Снова включи стенд и проверь `GET /api/ping` / `GET /api/status` без UART timeout. Не менять прошивку ESP по OTA ради этого теста.

Питание: S-30-5 по BOM — **только стенд**, не потолок без PE; для потолочного монтажа предусмотрен Class II 5 V PSU. Общий software current limit оставить **3000 мА**, не увеличивать ради подсветки.

## 5. Первый практический тест

1. Открой уже установленное Android-приложение, убедись, что ARDU Online. Приложение и ESP обновлять не нужно.
2. Выбери «Фон» → **F01 «Цвет»**. Наблюдай кольцо полные 35–40 секунд. Не нажимай временные карточки «Северное сияние / Океан / Космос» старого Android — они пока **макросы старого API**, а не новые P-сцены.
3. При желании F01 можно запустить без приложения через PowerShell (подставь фактический IP устройства):
   `Invoke-RestMethod "http://192.168.0.4/api/ambient/effect" -Method Post -ContentType "application/json" -Body '{"id":"F01"}'`.
4. Переключись на страницу «Свет»: Ambient должен остановиться, L01 включиться. Вернись во «Фон» и выбери F01 снова. Коротко проверь Music и Night, чтобы убедиться, что UART/FastLED не зависли.
5. Без Wi-Fi анимация должна продолжаться на Nano; после холодного отключения/включения основного питания должен стартовать L01. Не менять расписание Alarm/Dawn ради этого теста.
6. Отметь отдельно, как выглядят **Северное сияние / Космос / Камин**. Полезен один ролик 35–40 секунд со всем кольцом. Реальный hardware PASS нельзя заменить тестом CI.

## 6. Стоп-условия и возврат

Остановить тест при случайных reset, зависании UART, пропадании питания, мигании/искажении LED, нагреве или непредусмотренном поведении L01. Проверить схему/измерения при снятом питании.

Для возврата к стандартным F01/F02/F03 открыть `04_Прошивка/nano_ardu_v1/nano_ardu_v1.ino`, нажать Verify/Upload **с той же безопасной изоляцией D0**, снова проверить Serial `1`→`O 1` и `GET /api/status`. Никакой P-пресет ещё не имеет стабильного API/UART или EEPROM layout; пользовательские старые настройки не мигрировались.

**Следующий этап только после физической проверки:** уточнить реальные палитры, скорость и видимые дефекты P01/P04/P05, затем отдельным небольшим шагом доработать архитектуру и запас Flash для релиза.
