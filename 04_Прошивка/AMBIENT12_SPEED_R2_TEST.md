# ARDU — Nano Ambient12 R2: непрерывная скорость атмосферных пресетов

**Дата:** 2026-10-09  
**Статус:** [GitHub Actions Arduino Verify 37966945125](https://github.com/dronrome1245/ARDU/actions/runs/37966945125) **PASS**. Полный Nano R2 **29336/30720 Flash, 1286/2048 globals SRAM**; прирост против старого полного R1 **+30 Flash, +4 globals**. Реальный Upload и visual PASS ещё НЕ выполнены.  
**Заменяет только алгоритм времени анимации в полной Nano; не изменяет ESP, Android, протокол, EEPROM, питание и ограничитель тока.**

## 1. Почему нужна эта версия

В физически использовавшемся полном Nano source `nano_ambient12_v1.ino` значение `dynamics` у всех P01..P12 преобразовывалось только в три множителя:

- 0..69 → медленно;
- 70..170 → обычно;
- 171..255 → быстро.

Значения 182, 190 и 225 дают **одинаковую** скорость. Android и ESP записывают новое значение, но Nano отображает только один из трёх режимов.

## 2. Что изменено в R2

Полный самостоятельный скетч: `04_Прошивка/nano_ambient12_v2/nano_ambient12_v2.ino`.

- `dynamics` 0..255 задаёт **256 разных коэффициентов скорости** 512..2042 единиц Q16/мс — изменение скорости плавное и монотонное, разница сильнее заметна на большой дистанции ползунка.
- Минимум: один логический тик примерно каждые 128 мс, максимум: примерно каждые 32 мс. Каждые 40 мс обновляется кадр (верхняя граница частоты обновления не меняется).
- Использован один счётчик `presetPhaseQ16` (4 байта SRAM). Время считается по разнице `millis()`; изменение ползунка **не сбрасывает** фазу.
- P11 «Дыхание»: полный цикл вместо десятков секунд/минут занимает примерно 16 с при 0 и около 4 с при 255.
- P02 «Закат на Бали» и P07 «Лунный свет» **преднамеренно почти статические**, регулировка изменяет скорость мягких мерцаний, но не превращает их в бегущие эффекты.
- P01/P03/P04/P05/P06/P08/P09/P10/P12 меняют скорость движения/мерцания; P11 меняет период дыхания.
- EEPROM layout `PresetPersist` (29 байт), текущие значения P01..P12, `D 115`, UART опкоды 111..115, `GET/POST /api/ambient/preset*`, ограничение тока и два зеркальных DATA остаются совместимыми.
- Новая boot-строка Nano `ARDU1 3` (**ревизия полного скетча**); ESP по-прежнему может показывать `nano_fw=ARDU_V2` по наличию 12 пресетов — это название уровня функций, не детальная версия boot-кода.
- Старая `nano_ambient12_v1` **не тронута**, служит откатом.

## 3. Автоматическая проверка перед Upload

GitHub Actions **Arduino Verify** для этой ветки обязан завершиться `PASS`:

1. Скрипт выделяет из реального R2 .ino функции вычисления фазы и отрисовки всех 12 сцен и собирает их как C++ host test с 44 LED; копии отдельного алгоритма в тесте нет.
2. Проверяются все 256 скоростей, различие 182/190/225, смена скорости без скачка фазы, rollover `millis()`, одинаковый результат за 250 кадров против одного накопленного интервала и изменение кадра для каждого P01..P12.
3. Компилируются *полные* Nano R1 и R2 для Arduino Nano ATmega328P **Old Bootloader** и оригинальных FHT/FastLED.
4. Flash и статическая SRAM R2 сравниваются с исходным R1. **CI PASS:** R1 29306 Flash/1282 globals; R2 29336 Flash/1286 globals; остаток до лимитов компилятора 1384 байт Flash и 762 байта SRAM для стека/локальных переменных. Внутренний 95%-ориентир Flash 29184 B превышен на **152 байта**; это принимается лишь как тестовый RC, не release freeze. Проверка глубины стека и питания — отдельные **аппаратные**, CI их не заменяет.
5. Отдельные бинарники `.hex` старой и новой версии публикуются для возможного rollback.

## 4. Физический gate: только один канал 44 LED

**Не делать Upload при неуспешном CI или сомнительных подключениях.** Перед тестом убедиться, что питание Nano/ESP/WS2812B и общая земля уже проверены; на потолке/230 В эксперименты запрещены.

1. Обесточить стенд: отключить сетевой блок S-30-5 и USB Nano. Не разъединять работающие провода под напряжением.
2. Для USB-прошивки временно отключить **только** провод `ESP TX0/GPIO1 → Nano D0/RX` при снятом питании (иначе ESP и USB-UART могут конфликтовать). Фото/схема стенда имеют приоритет.
3. Подключить Nano USB к ПК. В Arduino IDE открыть **полный скетч** `nano_ambient12_v2/nano_ambient12_v2.ino`, выбрать Arduino Nano → ATmega328P (Old Bootloader), правильный COM, нажать **Verify**. Сравнить количество Flash/SRAM с CI. При ошибке Upload не выполнять.
4. При успешном Verify нажать Upload. Пока ESP RX-провод снят, с Serial Monitor 115200 проверить **boot `ARDU1 3`** и штатную команду статуса `2`. Не путать software level `ARDU_V2` с boot revision.
5. Закрыть Serial Monitor, снова обесточить USB и S-30-5, вернуть `ESP TX0/GPIO1 → Nano D0/RX` в прежнюю схему. Проверить общую GND. После включения `GET /api/ping`, `GET /api/status`, `GET /api/ambient/presets` должны отвечать; `ambient_presets.supported` остаётся `true`.
6. На **одном** заранее испытанном 44-LED кольце D6 (D7 второе не добавлять в этот же тест) выбрать P11 «Дыхание», яркость ≤40%, динамика 0 → 128 → 255. Убедиться, что полное дыхание ускоряется плавно (~16 → ~7 → ~4 с) без рывка/потери UART. На P01/P03/P05/P12 сравнить значения 20, 130, 240 (не требовать визуального отличия соседних значений за секунду).
7. На смартфоне изменить значение, перейти на другой пресет и обратно, убедиться, что `GET /api/ambient/presets` показывает сохранённое индивидуальное `dynamics`; после холодной перезагрузки оно сохраняется. Двойное кольцо **не подключать**, лимит тока до нагрузочного теста держать 3000 мА или ниже.
8. Кратко проверить L01 ON/OFF и Music M01, Night и RTC; не считать это полной приёмкой остальных функций.

## 5. Стоп/откат

При несовпадении установленной ревизии, отсутствии UART, случайных вспышках, высокой температуре, срывах ответа ESP или нарушении плавности **остановить физическую проверку** и вернуться к ранее рабочему полному `nano_ambient12_v1/nano_ambient12_v1.ino` через безопасную USB-процедуру. Не перепрошивать ESP; изменения касаются только Nano.

После успешного 44-LED теста остаются открытыми: реальная максимальная глубина стека (766 B статического резерва в R1 не равны свободному runtime stack), оба кольца 44+44, силовые измерения, защищённый ARDU-DIRECT без роутера, полная проверка всех 12 сцен на железе.
