# Режимы работы ARDU

Версия: 0.1  
Дата: 2026-09-06

## 1. Основание

Этот документ фиксирует функциональную модель режимов перед проектированием прошивки и нового Wi‑Fi приложения.

Источники:

1. пользовательский проект MIT App Inventor `Ardublock2.aia` (`LumpV3.1`), экраны `Disco`, `Obichniy`, `Nochnik`, `FON`;
2. ColorMusic AlexGyver v2.x как исходная база алгоритмов светомузыки;
3. актуальные решения ARDU: два синхронных кольца WS2812B, один MAX9814, один DS3231, управление по Wi‑Fi.

Важно: старый интерфейс и старые однобайтовые команды не являются обязательным контрактом. Сохраняется функциональный смысл режимов.

---

## 2. Верхний уровень режимов новой лампы

В ARDU принимаются пять пользовательских разделов:

1. **Обычный свет** — постоянное белое освещение двух WS2812B-колец.
2. **Светомузыка** — эффекты, зависящие от звука MAX9814.
3. **Фоновые эффекты** — декоративная анимация без зависимости от музыки.
4. **Ночник** — спокойное постоянное/медленно меняющееся свечение малой яркости.
5. **Будильник / рассвет** — автономный сценарий по времени DS3231.

Отдельные точечные светильники комнаты сохраняются как независимое освещение, но ARDU теперь также имеет собственный пользовательский режим обычного света.

---

## 2.1. Обычный свет — L01

Стабильный ID: `L01`.

Минимальный набор v1:

- все LED двух колец показывают одинаковый постоянный цвет;
- `Kelvin` mode: приблизительный белый 1800..6500 K;
- app presets: 2700 K / 4000 K / 6000 K;
- произвольный RGB color;
- регулируемая яркость;
- ВКЛ/ВЫКЛ из приложения;
- при холодной загрузке после появления питания от второй клавиши 230 В обычный свет должен включаться автоматически;
- хлопковый выключатель на MAX9814 должен переключать обычный свет локально, без телефона;
- в приложении должна быть возможность включить/отключить функцию хлопкового выключателя;
- программный лимит тока обязателен.

WS2812B формирует RGB-имитацию температуры белого, а не настоящий CCT-белый. Kelvin mapping считается приблизительным пользовательским представлением и проходит отдельную визуальную проверку.

Точная логика распознавания хлопка (одиночный/двойной, окно времени, порог, защита от музыки) определяется отдельным hardware test до общей прошивки.

Подробно: `04_Прошивка/LIGHT_CLAP_REQUIREMENTS.md`.

## 3. Светомузыка — базовый набор v1

Набор ниже основан на режимах старого `Disco` и ColorMusic, но стробоскоп M06 исключён владельцем из целевого функционала.

| ID | Режим | Оставляем | Основные параметры |
|---:|---|---|---|
| M01 | VU градиент | да | плавность, чувствительность/автогейн, яркость активных, фон |
| M02 | VU радуга | да | плавность, скорость радуги, чувствительность/автогейн, яркость |
| M03 | 5 полос | да | плавность, чувствительность, яркость |
| M04 | 3 полосы | да | плавность, чувствительность, яркость |
| M05 | 1 полоса / доминирующая полоса | да | подрежим частоты, плавность, чувствительность |
| M07 | Цветная подсветка | переносим в фоновые эффекты | цвет/скорость/насыщенность в зависимости от подрежима |
| M08 | Бегущие частоты | да | подрежим частоты, скорость, чувствительность |
| M09 | Анализатор спектра | да | шаг цвета, начальный цвет/HUE, чувствительность |

### 3.1. Подрежимы M05 — «1 полоса»

Из `Ardublock2.aia` и ColorMusic подтверждены:

- `3 частоты`;
- `Низкие`;
- `Средние`;
- `Высокие`.

Для новой версии эти четыре значения сохраняются как явный параметр `band_mode`.

### 3.2. Подрежимы M08 — «Бегущие частоты»

Сохраняются те же варианты:

- `3 частоты`;
- `Низкие`;
- `Средние`;
- `Высокие`.

## 4. Фоновые эффекты — базовый набор v1

Старый `FON` содержал интерфейс следующего/предыдущего эффекта и автоперебора, но блоки управления эффектами были фактически не закончены. Поэтому конкретный список фоновых эффектов строим из подтверждённых подрежимов ColorMusic и старого `Disco`.

Базовые эффекты:

| ID | Эффект | Параметры |
|---:|---|---|
| F01 | Постоянный цвет | HUE/цвет, насыщенность, яркость |
| F02 | Плавная смена цвета | скорость, насыщенность, яркость |
| F03 | Бегущая радуга | скорость, шаг радуги, яркость |

Общие функции раздела:

- следующий эффект;
- предыдущий эффект;
- автоперебор эффектов;
- период автоперебора — добавить в новой версии, потому что старый интерфейс имел только переключатель.

Дополнительные декоративные эффекты можно добавлять позже, но они не входят в обязательный MVP.

## 5. Ночник — базовый набор v1

Старый экран `Nochnik` показывает, что планировались:

- включение/выключение ночника;
- расписание перехода в ночной режим;
- расписание возврата;
- цветовая температура;
- яркость.

Однако блоки обмена с Arduino в старом `.aia` не завершены.

Поскольку WS2812B не является настоящей CCT-лентой с отдельными тёплым/холодным белыми каналами, для ARDU параметр «цветовая температура в K» не переносится буквально.

Для v1 принимаем:

- включение/выключение;
- яркость;
- цвет через HUE/насыщенность;
- сохранённый спокойный цвет по умолчанию;
- расписание ночника — оставить как функцию, но включить в MVP только после будильника, если не усложняет прошивку.

---

## 6. Будильник / рассвет — базовый набор v1

Из старого `Obichniy` подтверждены функции:

- будильник ВКЛ/ВЫКЛ;
- время будильника;
- длительность рассвета;
- максимальная яркость;
- ранее использовался параметр цветовой температуры;
- запрос/установка времени RTC;
- диагностика потери времени RTC.

В ARDU принимаем:

| Параметр | Решение v1 |
|---|---|
| Время будильника | оставить |
| ВКЛ/ВЫКЛ | оставить |
| Длительность рассвета | оставить |
| Максимальная яркость | оставить |
| Начальный цвет рассвета | добавить как явный RGB/HUE-параметр |
| Конечный цвет рассвета | добавить как явный RGB/HUE-параметр |
| Цветовая температура K | не использовать буквально для WS2812B |
| Синхронизация RTC с телефоном | оставить |
| Ручная установка RTC | оставить как сервисную функцию |
| Остановка текущего рассвета | обязательно оставить |

Рассвет должен работать автономно без телефона и Wi‑Fi, если физическое питание лампы включено второй клавишей.

## 7. Общие параметры светомузыки

Старое приложение имело два отдельных бегунка:

- яркость «горящих» светодиодов;
- яркость «не горящих» светодиодов.

Эту модель сохраняем, но после аппаратной проверки M03 значение по умолчанию для музыкальных режимов — полное гашение фона. Пользователь по-прежнему может отдельно поднять фоновую яркость.

Общие параметры v1:

- `active_brightness` — яркость активных пикселей;
- `background_brightness` — яркость фоновых пикселей; default для музыкальных режимов = `0`;
- `audio_sensitivity` — чувствительность там, где она применима;
- `smoothing` — плавность там, где она применима;
- `noise_calibration` — отдельная команда калибровки микрофона;
- программный лимит общего тока обоих колец.

Не все параметры показываются во всех режимах. UI должен отображать только применимые настройки.

---

## 8. Что из старого приложения не переносим как функцию

Не переносим:

- Bluetooth-выбор устройства на каждом экране;
- хранение адреса HC-05 как основной модели соединения;
- отдельное переподключение Bluetooth при открытии каждого экрана;
- старые команды управления «люстрами» `3/4` как внешний контракт; новый L01 получает собственную семантику и новый API;
- буквальную настройку Kelvin для WS2812B;
- старые однобайтовые команды как внешний API.

Старые команды сохраняются только как исторический материал для понимания поведения старого проекта.

---

## 9. MVP новой прошивки

Первый рабочий функциональный комплект должен включать:

1. синхронный вывод двух колец;
2. F01 постоянный цвет — для проверки света и Wi‑Fi;
3. M01 VU градиент — первый звуковой режим;
4. M03 или M04 частотная светомузыка после проверки FHT;
5. калибровку MAX9814;
6. будильник с простым рассветом;
7. чтение/запись настроек;
8. управление через новый локальный Wi‑Fi API.

После этого по очереди добавляются остальные режимы ColorMusic.

До кодирования полного набора отдельно утвердить:

1. оставить ли все девять музыкальных режимов или часть скрыть как «расширенные»;

4. нужен ли автоматический ночник по расписанию в первой версии;
5. какие дополнительные фоновые эффекты, кроме F01–F03, нужны после MVP.

## Ambient speed semantics + app presets — 2026-10-07

**РЕШЕНИЕ D-102:** field `speed 1..255` for F02/F03 has monotonic user semantics: larger value = faster visual movement.

Previous F03 implementation used `ambientRuntimeHue += speed` every fixed 30 ms. Because hue is uint8, high values wrapped (e.g. 247 behaves like -9), so slider response was non-monotonic/aliased.

Current source:
- converts speed to frame interval;
- increments runtime hue by one per frame;
- F02 and F03 use the same direction: 1 slow → 255 fast.

Android popular-scene presets do **not** create new F IDs. They map to existing effects:
- Северное сияние → F02 tuned hue/saturation/brightness/speed;
- Закат → F01 warm static profile;
- Океан → F02 blue dynamic profile;
- Космос → F03 darker rainbow profile.

## D-104 — Future Ambient excludes F02/F03 (2026-10-08)

**Последнее решение владельца:** F02 и F03 больше не нужны в будущем пользовательском режиме «Фон»; F01 (постоянный цвет) оставить.

**Совместимость:** перечисленные выше F02/F03 являются фактами о текущей/прошлой реализации. На этапе фиксации идеи исходники и физическая прошивка НЕ изменялись. Не удалять F02/F03 из v1, пока не согласованы и не проверены новые сцены.

**Идея, не утверждённое ТЗ:** 12 атмосферных пресетов / четыре компактных семейства эффектов. Подробно: [AMBIENT_PRESETS_CONCEPT.md](AMBIENT_PRESETS_CONCEPT.md). Номера P01…P12 условны, не стабилизированы.

## D-114 — полная Nano Ambient12 R2 с непрерывной скоростью (2026-10-09)

Только **новый отдельный source candidate** `nano_ambient12_v2/nano_ambient12_v2.ino` (boot `ARDU1 3`), не прежняя фактически установленная R1: `dynamics` P01..P12 теперь линейно управляет скоростью локального автономного времени эффектов, 256 различных коэффициентов Q16 без скачка при изменении ползунка, логический тик ~128..32 мс. P11 «Дыхание» изменено на цикл ~16..4 с. P02 «Закат» и P07 «Лунный свет» сохраняют почти статический характер; скорость меняет только мягкое движение света. F01 и Music/Night/Alarm не изменены.

[Arduino Verify 37966945125](https://github.com/dronrome1245/ARDU/actions/runs/37966945125) PASS (Flash 29336/30720; static SRAM 1286/2048, прирост 30B/4B). Фактическая визуальная/силовая/stack приёмка не выполнена. Без новой успешной физической проверки **не объявлять проблему закрытой на устройстве**. Пошаговый gate: `AMBIENT12_SPEED_R2_TEST.md`.
