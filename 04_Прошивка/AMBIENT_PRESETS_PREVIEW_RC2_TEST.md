# ARDU — тест Nano Ambient Preview RC2 (один .ino)

**Дата:** 2026-10-08  
**Статус:** исходник и HEX **CI PASS**, локальный Arduino IDE Verify и физический Upload владельца ещё не подтверждены.  
**Причина новой ревизии:** RC1 выдала `fatal error: ambient_preset_probe.h: No such file or directory` на Windows, несмотря на сообщение владельца, что файл находится в той же папке. Конкретная причина поведения Arduino IDE не установлена. В RC2 нестандартный заголовок целиком встроен в `.ino`.

## 1. Что открыть

**Единственный нужный файл проекта для этой версии:**

`04_Прошивка/nano_ambient_preview_rc2/nano_ambient_preview_rc2.ino`

Он содержит полную Nano v1 со всеми Music/L01/Night/Alarm/Clap/FHT/RTC/UART режимами и экспериментальные эффекты P01/P04/P05 внутри одного файла. **`ambient_preset_probe.h` скачивать, копировать, добавлять во вкладки Arduino IDE или создавать рядом НЕ нужно.**

- [Исходный .ino на GitHub](nano_ambient_preview_rc2/nano_ambient_preview_rc2.ino)
- [GitHub Actions / Arduino Verify — успешный прогон RC2](https://github.com/dronrome1245/ARDU/actions/runs/37814719230)
- [Готовый HEX RC2](https://github.com/dronrome1245/ARDU/actions/runs/37814719230/artifacts/11567275089) — альтернатива; для Arduino IDE проще открыть `.ino`.

### Для Windows из GitHub

Вариант A (предпочтительно): в `C:\ARDU` выполнить `git switch main` → `git pull`, открыть в Arduino IDE полный путь к `nano_ambient_preview_rc2.ino`.

Вариант B (без Git): открыть ссылку на исходник выше → **Download raw file** (не HTML страницы GitHub). Положить один полученный файл в папку с **точным названием** `nano_ambient_preview_rc2`, например:

`C:\Users\Пользователь\Downloads\nano_ambient_preview_rc2\nano_ambient_preview_rc2.ino`

В проводнике Windows включить «Вид → Показать → Расширения имён файлов» и проверить, что расширение именно `.ino`, не `.ino.txt`. Старую папку `nano_ambient_preview_rc1` больше не открывать.

## 2. Проверка Arduino IDE

1. В меню **File → Open** открыть **`nano_ambient_preview_rc2.ino`**, а не прошлый `RC1`.
2. Tools → Board → **Arduino Nano**. Tools → Processor → **ATmega328P (Old Bootloader)**.
3. Установленные стандартные зависимости остаются обязательны: **FastLED** и оригинальная **FHT** из `04_Прошивка/libraries/FHT` (использованная в полной Nano v1). Встроенным стал только `ambient_preset_probe.h`, не FastLED/FHT.
4. Нажать **Verify** до любых изменений проводки. Ориентир успешной компиляции для среды CI: **29376 байт Flash, 1234 байт globals SRAM**; результат на ПК может отличаться из-за версий FastLED/Arduino core.
5. Если Verify прошёл — только затем переходить к реальному Upload по п. 3 с учётом безопасного питания. Если повторилась ошибка, прислать **первые строки лога Verify и строку с путём открытого .ino**; больше искать `ambient_preset_probe.h` не требуется.

## 3. Безопасная аппаратная загрузка (после Verify)

1. До работы записать текущие версии и настройки: `GET /api/ping`, `GET /api/status` и `GET /api/settings`, сохранить доступ к стандартной прошивке `04_Прошивка/nano_ardu_v1/nano_ardu_v1.ino` для восстановления. Текущий main не гарантирует byte-for-byte тот же бинарник, что уже был загружен в Nano.
2. **Полностью отключить внешнее питание и USB**, затем временно отсоединить `ESP TX0 / GPIO1 → Nano D0 / RX`. Делитель `Nano D1 / TX → ESP RX` не переставлять. `RESET Nano` оставить свободным.
3. Проверить, что питание USB Nano и внешние +5 В ленты/узла **не параллелятся без развязки** и что отсутствует питание выключенной ленты через DATA; при неясной разводке **не подключать USB**, сначала уточнить схему.
4. Arduino Nano / ATmega328P Old Bootloader / правильный COM → **Upload**. ESP8266/Android прошивать не нужно.
5. В Serial Monitor **115200, Newline** проверить команды `1` → `O 1`, `2` → `D 2 ...`; `4` → `D 4 ...`, если DS3231 синхронизирован.
6. Закрыть монитор, **снова полностью снять питание**, восстановить `ESP TX0 → Nano D0`, включить стенд и проверить `GET /api/status`. Если UART перестал отвечать — не переходить к тесту сцен, проверить исходную разводку/прошивку.
7. `S-30-5` с металлическим корпусом согласно BOM — только стенд (не потолок без PE). Лимит тока оставить **3000 мА**; не увеличивать ради теста.

## 4. Что должно быть на кольце

В Android открыть вкладку **«Фон»** и выбрать **F01 «Цвет»**. Это временный запуск демонстрации; другие старые Android-карточки «Северное сияние / Закат / Океан / Космос» ещё работают как макросы старого API, а не как новые P-scene ID.

| Интервал с момента выбора F01 | Сцена |
|---|---|
| 0–8,2 с | **Северное сияние P01**: широкие бирюзово-зелёно-фиолетовые зоны |
| 8,2–16,4 с | **Космос P04**: тёмный фон, отдельные плавно затухающие звёзды |
| 16,4–24,6 с | **Камин P05**: нерегулярное тёплое мерцание |
| 24,6–32,8 с | Прежний **F01**: постоянный цвет |
| Далее | Цикл повторяется |

Сними видео **35–40 секунд**, чтобы весь цикл был виден. Коротко проверь выход из «Фон» в «Свет» и возврат, а также отсутствие зависаний Music/Night/RTC. После холодной подачи питания по-прежнему должен включаться L01. **Видеотест, стабильность, потребление и два кольца ещё НЕ проверены.**

## 5. Возможность отката

При сбое не менять ESP. После снятия питания и отключения `ESP TX → Nano D0` для Upload загрузить обычный `04_Прошивка/nano_ardu_v1/nano_ardu_v1.ino` (без preview флага), затем восстановить UART и проверить команды `1`→`O 1` и `GET /api/status`. Стандартная прошивка не требует отдельного `ambient_preset_probe.h` при сборке без experimental flag, а новые сцены/новый протокол не сохранялись в EEPROM.

**Это проверочная полная RC, НЕ окончательный release:** CI Flash `29376 / 30720` (на 192 байта выше мягкого ориентира 95%); глобальная SRAM `1234 / 2048`; реальный запас стека, ток и температура не подтверждены.
