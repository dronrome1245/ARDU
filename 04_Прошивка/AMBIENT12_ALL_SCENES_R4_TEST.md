# ARDU Nano Ambient12 R4 — все 12 фоновых сцен действительно анимируются

**Дата:** 2026-10-09. **Статус:** [Arduino Verify 37975908088](https://github.com/dronrome1245/ARDU/actions/runs/37975908088) **PASS**, полный HEX R4 создан; реальный USB Upload и визуальный PASS всех сцен ожидаются.  
**Основание:** владелец сообщил, что на собранной лампе «сейчас работает только дыхание», и потребовал исправить все сцены сразу.

## 1. Состав исправления

Полный однофайловый скетч: `04_Прошивка/nano_ambient12_v4/nano_ambient12_v4.ino`.

Причина прежнего дефекта — большинство сцен использовали `phase = t >> 2`: полный цикл сдвига 8-битного смещения занимал примерно 33–131 с, а подсветка отдельных эффектов была слишком слаба. В R4 все P-сцены рисуются от общего `phase = (uint8_t)t`, а смена характеров движения реализована **в пиксельном renderer каждого пресета**, без изменения пользовательской шкалы скорости.

| ID | После исправления | Что должно быть видно |
|---|---|---|
| P01 | Северное сияние | Два плавных разнонаправленных бирюзово-зелёных цветовых занавеса |
| P02 | Закат на Бали | Тёплый цветовой градиент остаётся, по нему проходит светящаяся волна |
| P03 | Океан | Движущиеся голубые гребни на тёмно-синем фоне |
| P04 | Космос | Несколько разных светлых звёзд плавно и независимо мерцают |
| P05 | Камин | Неравномерное быстрое янтарно-оранжевое мерцание по кольцу |
| P06 | Свечи | Более мягкое и ровное золотое колебание, отличающееся от P05 |
| P07 | Лунный свет | Проходящие медленные тени на холодном малонасыщенном свете |
| P08 | Лес | Зелёные подвижные узоры и отдельные золотые солнечные блики |
| P09 | Неон | Сине-розовые сегменты смещаются, яркость пульсирует |
| P10 | Лава | Текучие тёмно-красные и оранжевые сгустки |
| P11 | Дыхание | **Не изменено**: цикл ~20,2 с на 0 и ~4,1 с на 255, однородное дыхание |
| P12 | Радуга | Полный цветовой спектр вращается по кольцу |

Большее `dynamics` ускоряет анимацию во всех 12 случаях. В R4 сохранена механика часов, включая непрерывную 256-уровневую скорость и отсутствие сброса фазы при изменении ползунка; замены числовых ID, HTTP, EEPROM и UART **нет**. Два физических кольца получают один зеркальный 44-пиксельный кадр через D6/D7.

Отдельно сохранены R3 `nano_ambient12_v3.ino` и его HEX как rollback. R4 при включении Nano печатает `ARDU1 5`; ответ ESP `nano_fw:ARDU_V2` означает поддержку P01..P12, но **не** номер ревизии boot.

## 2. Автоматический gate до установки

В GitHub Actions **Arduino Verify прошла полностью** ([CI 37975908088](https://github.com/dronrome1245/ARDU/actions/runs/37975908088)):

1. Host C++ тест реальных функций из нового полного Nano .ino на модели 44 HSV-пикселей (без копирования алгоритмов в тест).
2. Для **каждого** P01..P12 сравнить кадры, полученные при `dynamics=0` и `255` за 2 секунды. Необходимо увидеть изменения минимум 3 светодиодов и значимое суммарное изменение HSV; проверить, что смена «Динамики» меняет **результат отрисовки**, а не только служебное значение.
3. Подтвердить, что Q16-часы и пиксельный рисунок P11 скопированы из R3 без изменения; проверка на переполнение `millis()` и корректное накопление времени по частым кадрам.
4. Собрать полностью самостоятельный `nano_ambient12_v4.ino` в изолированной папке Arduino Nano (ATmega328P Old Bootloader) с текущими оригинальными FHT/FastLED; сравнить Flash и глобальную SRAM с полной R3. **Если не собирается или превышен абсолютный лимит Flash — Upload запрещён.** Целевой программный предел R4: ≤30300 B Flash и ≤1360 B глобальных SRAM. Рекомендованный 95%-ориентир Flash доработать позже; результат не заменяет физическую проверку стека и тока.
5. **CI результат:** R3 **29376/30720 Flash, 1286/2048 globals SRAM** → R4 **29410/30720 Flash, 1286/2048 globals SRAM** (+34 Flash/+0 SRAM), запас 1310 байт Flash и 762 байта SRAM для локальных переменных/стека; worst-case стек не измерен. Мягкий ориентир ≤95% Flash (29184 байта) превышен на 226 байт. Отдельный HEX R4 `ardu-nano-ambient12-v4-all-moving-rc1` создан, прежний HEX полной R3 доступен для отката. Exact-source host показал движение всех двенадцати кадров при 0/255; P04 после усиления имеет 9 изменяющихся звёзд и существенную суммарную разницу HSV.

## 3. Аппаратная приёмка: один 44-LED канал

Использовать только уже проверенный стенд с **одним кольцом 44 LED на D6**, яркость ≤40%, программный current limit ≤3000 мА. Не подключать второй круг и не выполнять новую разводку в этом шаге.

1. `cd C:\ARDU` → `git pull`. В Arduino IDE открыть `04_Прошивка/nano_ambient12_v4/nano_ambient12_v4.ino`. Board **Arduino Nano**, Processor **ATmega328P (Old Bootloader)**, правильный COM, **Verify**. Перед Upload сверить размер Flash/SRAM с GitHub CI. Не делать Upload при любых ошибках компиляции.
2. **Полностью обесточить** блок питания стенда и отсоединить USB Nano. Снять только провод `ESP TX0/GPIO1 → Nano D0/RX` на обесточенной сборке; затем подключить USB Nano к ПК, выполнить Upload. Не трогать 230 В без необходимой квалификации.
3. Serial Monitor 115200: после Reset должен появиться `ARDU1 5`. Закрыть Serial Monitor, полностью снять питание/USB, вернуть `ESP TX0/GPIO1 → Nano D0/RX` и проверить общую землю перед включением.
4. После штатного включения выполнить `GET /api/ping`, `GET /api/status` и `GET /api/ambient/presets`. Должна сохраниться поддержка 12 пресетов и всех настроек. ESP и Android ради анимаций не перепрошивать.
5. В Android на вкладке **Фон** последовательно P01–P12 выставить `dynamics=128`, выбрать безопасную яркость (до 40%) и просмотреть **5–10 секунд на сцену**. Особенно убедиться, что видимо движутся P02/P04/P07, которые раньше выглядели статичными. Для каждой сцены — заметная перемена хотя бы нескольких светодиодов в течение 5 с.
6. У P01, P03, P05 и P12 повторить `dynamics=0 → 128 → 255`, сравнить замедление/ускорение. На P11 ещё раз проверить утверждённое «Дыхание» без изменения эффекта. Для P02 и P07 допускается нежная, но видимая волна, не быстрое мигание.
7. `GET /api/ambient/presets` должен отражать выбранный Pxx и самостоятельную пару яркость/динамика, в том числе после перехода на другую сцену и возвращения. При холодной перезагрузке настройки должны сохраняться, а L01/Music/Night/Alarm не должны регрессировать.

## 4. Условия остановки

Если лампа моргает нештатно, после Nano Upload теряется UART/ESP-status, появляются перезагрузки/нагрев или режим P11 изменился, **остановить тест**, вернуть полную R3 `04_Прошивка/nano_ambient12_v3/nano_ambient12_v3.ino` через безопасную USB-процедуру и зафиксировать неудавшийся gate. Не перепрошивать ESP, не увеличивать current limit и не подключать второе кольцо «для проверки».

Остаются отдельными от этого R4: worst-case runtime stack, реальный ток и нагрев на двух 44+44 кольцах, безопасность конечного 5 В БП и проверка ARDU-DIRECT без маршрутизатора. CI HEX — **не физический приёмочный акт**.
