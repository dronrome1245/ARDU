# ARDU — DAWN R1 hardware test

Дата: 2026-09-26

## Цель

Проверить первую световую реализацию рассвета отдельно от восстановления после reset.

DAWN R1:

- наследует пройденный ежедневный ALARM R1;
- сохраняет alarm settings в прежнем EEPROM формате;
- отдельно сохраняет настройки рассвета;
- при alarm trigger запускает рассвет;
- поддерживает ускоренный ручной `DAWN TEST`;
- `DAWN STOP` гасит кольцо немедленно.

## Defaults

- fade: 30 min
- max brightness: 120
- start hue: 8
- end hue: 32

Яркость растёт линейно от 0 до max. HUE движется по кратчайшей дуге HSV от start к end.

## Быстрый визуальный тест

После Verify/Upload:

```
STATUS
DAWN TEST 20
```

За 20 секунд кольцо должно плавно:

1. стартовать практически с нуля;
2. увеличивать яркость;
3. менять оттенок от START_HUE к END_HUE;
4. закончить на MAX_BR и остаться в состоянии `DAWN=HOLD`.

Во время теста несколько раз `STATUS`; UART errors быть не должно.

Затем:

```
DAWN STOP
STATUS
```

Кольцо должно погаснуть, `DAWN=IDLE`.

## Проверка параметров

```
MAXBR 64
STARTHUE 0
ENDHUE 64
DAWN TEST 15
```

После проверки вернуть:

```
MAXBR 120
STARTHUE 8
ENDHUE 32
```

## Проверка запуска от будильника

Для быстрого теста:

```
FADEMIN 1
ALARM CLEARLAST
ALARMSET HH:MM
ALARM ON
```

где HH:MM — следующая минута.

При срабатывании ожидаются:

```
EVENT ALARM_TRIGGER RTC=...
EVENT DAWN_START SOURCE=ALARM DURATION_S=60
```

Через 60 секунд:

```
EVENT DAWN_COMPLETE
```

После теста вернуть `FADEMIN 30`, если это остаётся желаемым default.

## Что R1 пока не проверяет

Если Nano перезапустить во время активного рассвета, R1 не восстанавливает прогресс. Это отдельная следующая итерация после прохождения визуального/trigger теста.
