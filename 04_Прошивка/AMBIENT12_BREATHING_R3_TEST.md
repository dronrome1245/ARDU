# ARDU — Nano Ambient12 R3: чуть медленнее «Дыхание» на минимуме

**Дата:** 2026-10-09.  
**Основание:** владелец подтвердил, что P11 «Дыхание» в R2 выглядит хорошо на реальной ленте, и попросил **немного уменьшить скорость только при динамике 0**.  
**Статус:** Nano R3 подготовлена для отдельной программной и аппаратной проверки. Результат физической загрузки R3 пока **не подтверждён**.

## Изменён только P11

Новый полный однофайловый скетч: `04_Прошивка/nano_ambient12_v3/nano_ambient12_v3.ino`.

- P11 «Дыхание» при динамике 0: цикл **~20,1 с** вместо прежних **~16,4 с**.
- При динамике 128: **~6,8 с**; при 255: **~4,1 с**, как раньше.
- Между значениями 0..255 скорость возрастает монотонно без трёх ступеней.
- Остальные 11 пресетов P01..P10/P12 сохраняют прежний расчёт времени **точно** (для них P11-поправка не вызывается).
- Рисунок, оттенок, яркость, EEPROM-структура 29 байт, HTTP API, UART 111..115, FastLED, два выходных D6/D7 и остальные режимы не меняются.
- Код работает автономно после отключения Wi-Fi; изменение значения не обнуляет фазу.
- Загружаемая новая ревизия Nano при старте печатает `ARDU1 4`. ESP продолжит возвращать `nano_fw:ARDU_V2`: это уровень функциональности, а не точная версия полного Nano-скетча.
- Полный скетч R2 сохранён для немедленного отката.

## Автоматический gate

Сборка Arduino Verify должна проходить полностью. Она проверяет исходные функции Nano R3 на хосте: плавность 256 значений P11, прежние скорости остальных 11 пресетов, период ~20,1 секунды при 0 / ~4,1 секунды при 255, отсутствие скачка при изменении скорости, цикл millis(), неизменность всех 12 рендереров и совместимость EEPROM/UART. Затем собираются полные Nano R2 и R3 под `arduino:avr:nano:cpu=atmega328old`; сравниваются Flash и статическая SRAM. Остаток SRAM не считается доказательством достаточного worst-case runtime stack.

## Один следующий аппаратный шаг после успешного CI

Стенд с **одним проверенным кольцом 44 LED**, без подключения второго кольца и без новых изменений питания:

1. `cd C:\ARDU`, `git pull`. Arduino IDE → открыть именно `04_Прошивка/nano_ambient12_v3/nano_ambient12_v3.ino`, выбрать **Arduino Nano**, **ATmega328P (Old Bootloader)**, правильный COM и нажать **Verify**.
2. При полностью снятом внешнем питании S-30-5 и отключённом USB **временно отсоединить только ESP TX0/GPIO1 → Nano D0/RX**. После этого подключить USB Nano к ПК и сделать **Upload**. Не перемыкать 5 В Nano напрямую на 3,3 В ESP.
3. Проверить в Serial Monitor 115200 новую boot-строку `ARDU1 4`. Закрыть монитор, снять USB/питание, восстановить ESP TX→Nano D0, проверить общую GND.
4. Включить штатное питание стенда. `GET /api/status` и `GET /api/ambient/presets` должны отвечать; Android 0.22.9 и ESP перепрошивать не нужно.
5. В приложении выбрать P11 «Дыхание» с **умеренной яркостью ≤40%**. Проверить динамику **0** (примерно 20 с на один цикл), затем 128 (~6,8 с) и 255 (~4,1 с). Переходить между значениями без повторного выбора P11: анимация должна продолжаться без перезапуска фазы.
6. На одном другом эффекте, например P03 «Океан», убедиться, что движение соответствует прежней R2. После перезапуска проверить, что выбранная динамика P11 сохранилась.

Если внезапно пропали UART, свет или стабильность, остановить тест и использовать проверенную R2 `04_Прошивка/nano_ambient12_v2/nano_ambient12_v2.ino` через ту же безопасную процедуру.

**Не повышать общий программный лимит выше 3000 мА** до теста питания двух колец. Отдельные открытые ворота: реальная глубина стека, 44+44 ток/температура, ARDU-DIRECT и полный осмотр остальных 12 эффектов. Этот небольшой апдейт не является полным аппаратным acceptance.
