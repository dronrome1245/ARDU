# ARDU — Ambient preset lab R1: первые три алгоритма

**Дата:** 2026-10-08  
**Статус:** SOURCE PROTOTYPE / CI PASS / PHYSICAL TEST NOT DONE.  
**Основание:** явная команда владельца «давай начнем тогда реализовывыть пресеты».  
**План:** [AMBIENT_PRESETS_IMPLEMENTATION_PLAN.md](AMBIENT_PRESETS_IMPLEMENTATION_PLAN.md).

## 1. Реализовано (не подменять аппаратную приёмку)

- `nano_ardu_v1/ambient_preset_probe.h` — три независимых рендера, записывающие кадр в существующий `CRGB leds[44]`:
  - `AURORA` = концепт P01 «Северное сияние»: несколько зелёно-голубо-фиолетовых областей с независимыми пространственными волнами;
  - `COSMOS` = концепт P04 «Космос»: тёмно-синий фон и до трёх точек-звёзд с разными фазами постепенного появления и затухания;
  - `FIREPLACE` = концепт P05 «Камин»: пространственно неодинаковые оранжевые огни, псевдослучайные цели с интерполяцией во времени, без резких кадровых скачков.
- Для всех: динамика 0..255 (в этом раннем прототипе три дискретных диапазона скорости), целочисленная математика, не используются `delay()` и дополнительные RGB-буферы/EEPROM/глобальная память. Не добавлены внешние opcode/API/режимы P.
- `nano_ardu_v1/tests/ambient_preset_probe_host.cpp` — самостоятельный C++ host test: 44 пикселя, разные кадры по сценам/времени/скорости, детерминированность, границы массива и значения HSV.
- `nano_ardu_v1/nano_ardu_v1.ino`: экспериментальная интеграция **только** через build flag `ARDU_AMBIENT_PRESET_PROBE=1`. На активном Ambient (в lab binary) с периодом 8 с показываются AURORA → COSMOS → FIREPLACE → оригинальные F01/F02/F03; последний период оставляет legacy-ветку достижимой для проверки **реального полного** Flash footprint. В обычной сборке `ARDU_AMBIENT_PRESET_PROBE=0`, все F01/F02/F03 и UART v1 работают как раньше.
- В lab preview `requestedBrightness` = 115 (около 45%) для Aurora/Fireplace и 64 (около 25%) для Cosmos, далее всё равно применяется Nano current limit. Это лишь безопасные начальные предложения из каталога, не утверждённые настройки каждого пресета.

- **ФАКТ:** три prototype renderer вместе с действующими режимами помещаются в абсолютный Flash limit Nano, в отличие от неподтверждённого предположения про 12 сцен.

- **ФАКТ ПО CI:** host tests и обе AVR-сборки прошли, но реальный внешний вид на светодиодах, CPU/ISR latency, ток и долговременная стабильность **не тестировались**.

## 3. EEPROM-инвентаризация без миграции

В `nano_ardu_v1.ino` зафиксированы старые смещения:

| Блок | EEPROM base | Примечание |
| --- | ---: | --- |
| Alarm | 0 | 0..9 |
| Dawn | 16 | 16..23 |
| Dawn runtime | 32 | 32..45 |
| Night | 64 | 64..76 |
| Light profile | 128 | отдельная v1 legacy schema |
| Clap | 192 | отдельная schema |
| Core | 224 | 224..229 |
| ExtendedPersist | **256** | magic `0xA1D1`, version 1; Music ×7 / legacy Ambient / audio / current limit |

`ExtendedPersist` помечен `packed`. Из структуры следует проектный расчёт **76 байт** (256..331), без изменения в данном шаге; фиксировать с `static_assert(sizeof(...))` при будущей EEPROM migration. Память устройства физически не читалась и пользовательские значения не изменялись.

## 4. Что намеренно не делали

- Никакой **физической загрузки Nano/ESP**, OTA, теста кольца, измерения тока и температуры.
- Не присваивали стабильные ID P01/P04/P05 и не утверждали полный каталог P01…P12/P12 «Радуга».
- Не меняли firmware/API/UART/EEPROM-контракты, Android или существующие четыре Android-макроса.
- Не удаляли F02/F03 из deployed/stock firmware; D-104 означает их будущий уход из пользовательского UI после миграции.
- Не объявляли физическую визуальную приёмку или готовый новый release v1.

## 5. Следующий небольшой этап

1. Сохранить baseline и результаты CI, не перепрошивая действующую ARDU.
2. Улучшить запас Flash минимум до внутреннего ориентира 95% и проверить worst-case стек при полнофункциональной сборке.
3. Перед **физическим** тестом этих сцен — выпустить и проверить один согласованный **полный** Nano release candidate по FINALIZATION_PLAN. Не прошивать standalone-прототип, не менять работающую конфигурацию без rollback.
4. На реальном 44-LED кольце принять скорость, палитры, сглаживание трёх сцен. Только после владельческого visual PASS согласовать финальный каталог и версионированные UART/API/EEPROM значения.
5. Два зеркальных 44+44 выхода, ARDU-DIRECT и нагрузочный тест остаются отдельными acceptance gates перед потолочной установкой.
