# ARDU — идея атмосферных пресетов для режима «Фон»

**Дата:** 2026-10-08
**Статус:** ИДЕЯ / НЕ УТВЕРЖДЕНА К РЕАЛИЗАЦИИ.
**Основание:** явное решение владельца: «F02 и F03 не нужен. остальное зафиксируй в репозитории как идею».
**Приоритет:** D-104, STATUS.md. Не путать эту концепцию с работающим API/UART или прошивкой.

## 1. Принятое решение vs открытая идея

**РЕШЕНИЕ владельца:** в **целевом пользовательском интерфейсе** Ambient:
- F01 «Постоянный цвет» сохранить как простой ручной режим.
- F02 «Плавная смена цвета» и F03 «Бегущая радуга» **не нужны**: их убрать из целевого пользовательского набора при следующей специально одобренной реализации.
- Не переиспользовать занятые ID F02/F03 под другие режимы без явной миграции.

**ИДЕЯ, не утверждение:** добавить 12 атмосферных сцен с различными пространственными и динамическими паттернами, а не с разной окраской одних и тех же трёх существующих эффектов. Номера `P01…P12` ниже являются рабочими обозначениями, **не frozen IDs**.

**ТЕКУЩИЙ ФАКТ о source:** Nano/ESP/Android всё ещё содержат F01/F02/F03; в Android сейчас есть четыре временных кнопки preset, часть из которых используют F02/F03. Решение D-104 само по себе не вносит изменений в код или устройства. Нельзя заявлять, что F02/F03 уже удалены. Уже подготовленная правка F02/F03 speed в Nano остаётся исторически в source, но не становится обязательным новым физическим gate после изменения целевого UX.

## 2. Каталог идей

| Рабочий ID | Название | Пространственная картина 44 LED | Динамика | Начальная яркость (идея) |
| --- | --- | --- | --- | --- |
| P01 | Северное сияние | Одновременно широкие зелёные, бирюзовые, синие и фиолетовые участки | Медленно текут и меняют форму | 45% |
| P02 | Закат на Бали | Янтарный, коралловый, розовый, приглушённый фиолетовый | Почти статичный градиент с еле заметным дрейфом | 50% |
| P03 | Океан | Глубокий синий фон, мягкие бирюзовые гребни | Неспешные волны по окружности | 40% |
| P04 | Космос | Тёмно-синий/фиолетовый фон, редкие холодные «звёзды» | Плавное появление/затухание без резких вспышек | 25% |
| P05 | Камин | Неравномерные красные, оранжевые и золотые языки света | Натуральное нерегулярное мерцание | 45% |
| P06 | Свечи | Равномерный тёплый янтарный с небольшими локальными отклонениями | Очень слабое мерцание | 25% |
| P07 | Лунный свет | Холодный бело-голубой, чуть неравномерный по окружности | Почти статичен | 20% |
| P08 | Лес | Тёмная зелень, изумрудные участки и редкие тёплые блики | Медленный мягкий дрейф | 35% |
| P09 | Неон | Контрастные cyan/magenta сегменты | Плавное вращение | 50% |
| P10 | Лава | Бордовый фон, оранжево-малиновые пятна | Медленное движение сгустков | 40% |
| P11 | Дыхание | Мятно-бирюзовая палитра | Вся окружность плавно светлеет и темнеет; условно 10 с/цикл | 30% |
| P12 | Радуга | Полный спектр по окружности | Равномерное вращение, **не старый F03** | 45% |

Важно: пресет P12 «Радуга» **не возвращает F03**. Это лишь кандидат в новом наборе сцен, с отдельным движком/профилем и иным UX; сам P12 тоже можно исключить на этапе согласования.

## 3. Функциональная модель — предложено, не реализовано

- На странице «Фон» оставить отдельный простой ручной **F01** (цвет / насыщенность / яркость), а пользовательские атмосферные сцены вывести как карточки с фотографиями, названиями и выделением активной сцены.
- Нажатие на карточку запускает пресет сразу; переход из другого раздела выключает прежний runtime-режим по действующим правилам.
- Для сцены доступны **«Яркость»** и **«Динамика»** (человеческий диапазон «Спокойно ↔ Активно»). Для почти статичных сцен динамику можно скрыть.
- Изменённые пользователем значения конкретного пресета запоминаются независимо от F01 и других пресетов.
- После потери Wi‑Fi анимация продолжается локально на Nano. При холодной подаче питания остаётся существующее поведение: стартовый L01, а не автозапуск Ambient.
- Два зеркальных кольца D6/D7 показывают одинаковый 44-LED кадр.
- Без резких стробоскопических вспышек; общий Nano current limit остаётся действующим (на физическом стенде пока 3000 мА).

## 4. Предложение по технической реализации

**Nano:** компактный preset-engine поверх существующего `CRGB leds[44]` и действующего неблокирующего `loop()`:
1. градиенты/волны;
2. мерцание/огонь;
3. отдельные редкие точки/звёзды;
4. дыхание/пульсация.

Палитры и параметры хранить преимущественно в `PROGMEM`. Использовать целочисленную арифметику, фиксированные буферы и `millis()`, без `delay()` и без `String` в критическом контуре. Не создавать новые параллельные RGB-буферы на 44 LED, пока не измерена SRAM.

**ESP / API — идея, не контракт:** возможный `POST /api/ambient/preset` с `{"id":"P03"}`, плюс readback ID/параметров в `GET /api/settings`. Android не отправляет числовые UART opcodes. Номера UART, схема выбора и форматы ответов пока **не назначены**.

**Persistence — идея:** отдельное версионированное хранение ID последней сцены, яркости/динамики и контрольной суммы; без промежуточных EEPROM writes на каждом шаге слайдера. Существующий v1 `ExtendedPersist` и его миграцию проверить до изменений. Сохранённые F01 настройки не терять.

**Риски:** на подтверждённой release-сборке Nano ранее было ~28 024 / 30 720 байт Flash и 1 070 / 2 048 байт global SRAM. Это историческое измерение; текущие изменения source (reset/speed) не имеют здесь нового compile/memory PASS. Предложенные четыре алгоритма и все 12 сцен **не гарантированно помещаются** в текущий ATmega328P. Не добавлять весь объём без нового compile gate.

## 5. Минимальная проверяемая реализация, если идея будет утверждена

1. Отдельно утвердить список и визуальное поведение P01…P12, решить судьбу P12 «Радуга».
2. Подготовить минимальный Nano prototype на трёх максимально отличающихся сценах: P01 Северное сияние, P04 Космос, P05 Камин. Сначала compile + flash/SRAM check, затем физическое кольцо на ограниченной яркости.
3. Только после PASS — решить алгоритмические семейства, полноту каталога, формат persistence, стабильные IDs, UART и HTTP API.
4. Затем отдельно убрать F02/F03 из нового user-facing Android UI; обновить совместимость ESP/Nano, не оставив старые кнопки или alias-макросы.
5. Последовательно проверить app→ESP→Nano, status/readback, power cycle, оба D6/D7 выхода, текущий лимит и независимые настройки.

**Запрет на преждевременную реализацию:** настоящим документом не утверждены новые ID, API маршруты, UART opcodes, EEPROM layout или изменение прошивки. Для начала программных изменений требуется отдельное решение владельца.
