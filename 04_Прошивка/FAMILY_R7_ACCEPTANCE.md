# D-128 — приемка семейного Night/Alarm (Nano R7 + ESP V5 + Android 0.22.16)

Статус: **план испытаний, не аппаратный PASS**. Существующая физическая Nano R6 сохраняется до **AVRDUDE write+byte-for-byte verify и функционального испытания R7**. Source compile/memory Nano R7 и ESP V5 уже PASS в GitHub CI.

## 0. Перед испытаниями

- Не подключать и не переподключать 230 В. Не монтировать лампы до отдельного Class II + 44+44 электрического gate. Для испытаний использовать уже безопасно запитанный низковольтный стенд.
- CI [run 43595155594](https://github.com/dronrome1245/ARDU/actions/runs/43595155594): Nano R7 **30 712/30 720 B flash** (только 8 B запаса) и **1 076/2 048 B global SRAM**, ESP V5 PASS. Android [run 43593418689](https://github.com/dronrome1245/ARDU/actions/runs/43593418689) PASS. Новые функции Nano без уменьшения размера запрещены.
- Сохранить `GET /api/status`, `GET /api/settings`, `GET /api/time` для возврата параметров. RTC должен быть валиден, временной пояс устройства должен соответствовать локальному времени.
- ESP V5 (Station/OTA с частными локальными credentials) → `GET /api/ping` показывает V5. Только после подтверждения прошивки ESP и её UART связи программировать Nano R7 через **проверенный** `tools/flash_nano_over_wifi.ps1`, AVRDUDE **write+byte-for-byte verify**, без `-V`; `/api/status` вновь отвечает; startup `ARDU1 8`.
- Проверить `GET /api/settings` → `alarm.family_schedule_supported:true`, `weekday_enabled:true`, `weekend_enabled:false`, `hold_minutes:15` на новых настройках (у уже настроенного устройства могут быть сохранённые значения). До этого Android должен скрывать элементы новой автоматики.

## 1. Android и обратная совместимость

- Приложение: открытие Свет/Музыка/Фон/Ночь/Будильник по очереди **не должно** менять `/api/status.mode`, включая активный Night и Dawn.
- Только явная кнопка ON/OFF или нажатие сцены меняет режим.
- Избранное: долгим нажатием выбрать четыре разных Pxx; быстрые кнопки запускают соответствующие сцены; после перезапуска приложения локальное избранное сохраняется, состояние активной сцены читается только из Nano.
- На старой R6 + ESP V4 семейная карточка скрыта, остальные 5 экранов, 12 сцен и RTC продолжают работать, нет запросов к неподдерживаемым опкодам.
- Пресет «Отдых» визуально доступен и не меняет сохранённый L01 профиль без явного выбора.

## 2. Night

- При отключённом расписании вручную включить Night вне временного окна: свет плавно появляется, без резкого скачка, около 16 с; вручную выключить: плавно гаснет.
- Включить расписание и поставить ON на ближайшую минуту: лампа плавно входит в Night, не требует Wi-Fi/телефона. OFF через 2–3 минуты: только активный Night плавно выключается.
- После автоматического ON переключить вручную на LIGHT/AMBIENT; граница OFF не должна гасить такой режим.
- На активном DAWN событие ON не прерывает рассвет.
- При холодном запуске внутри окна Night не должно быть вспышки L01.

## 3. Семейный рассвет

- Включить master alarm, `weekday_enabled:true`, `weekend_enabled:false`; установить будничное и выходное время разными. В субботу/воскресенье **будильник не запускается**, пока weekend disabled. При weekend enabled запускается по отдельному времени.
- Для проверок без ожидания нужного дня временно использовать RTC с тестовой датой на стенде, **только после резервного сохранения исходного времени/настроек**, вернуть корректное время DS3231 сразу после теста.
- Время в HH:MM — **конец** fade, начало за `fade_minutes` до него. Проверить переход до полуночи: если wake в 00:10 и fade30, старт 23:40 предыдущего дня, нужная будняя/выходная группа определяется по **дате wake**.
- Настроить `hold_minutes:1`; после достижения максимума рассвета авто-OFF примерно через 60 секунд. Вручную перейти на другой режим до окончания hold: он НЕ должен погаснуть. При `hold_minutes:0` рассвет остаётся в HOLD до ручного действия.
- Проверить что ручной/тестовый рассвет при holdMinutes>0 не гасится автоматически.
- Обеспечить запуск через DS3231 без телефона/Wi-Fi. Проверить restart во время RUNNING/HOLD, устойчивость EEPROM, повторных автотриггеров за день, что меняет дату wake.

## 4. После испытаний

- Вернуть исходные расписания/RTC/яркость/лимит тока, прочитать `/api/settings` заново и сохранить журнал результатов со временем и сырыми `/api/status`.
- Сначала Nano compile PASS → ESP/Android PASS → физический write+verify → функциональный тест, только после этого помечать D-128 hardware PASS.
- Полный 44+44 electrical/current/temperature и безопасный Class II PSU — независимые обязательные gate; они не закрываются программной приемкой.
