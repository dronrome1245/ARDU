# Архитектура системы

## 1. Контекст

ARDU управляет двумя неработающими круглыми потолочными корпусами, которые используются только как база для WS2812B. Основной белый свет комнаты отдельный и в ARDU не входит.

Задачи проекта:

1. обработка аудио и музыкальные эффекты;
2. синхронное управление двумя WS2812B-кольцами;
3. Wi‑Fi управление со смартфона;
4. RTC и световой будильник.

## 2. Логическая схема

```text
Мобильное приложение
        │
        │ домашний Wi‑Fi / HTTP
        ▼
   ESP8266 3,3 В
        │ UART
        ▼
   Arduino Nano
     │    │    │
     │    │    └── DS3231
     │    └────── MAX9814
     │
     ├── D6 ───── WS2812B корпус A (~43 LED)
     └── D7 ───── WS2812B корпус B (~43 LED)
```

Один Nano является единственным владельцем состояния обоих светильников. Оба кольца отображают синхронный кадр.

## 3. Силовая схема верхнего уровня

```text
вторая клавиша 230 В
        │
        ▼
S-30-5, 5 В / 6 А
        │
        ├── 5 В/GND → кольцо A
        ├── 5 В/GND → кольцо B
        ├── 5 В → Nano/MAX9814/DS3231
        └── 5 В → YP-8 → 3,3 В → ESP8266
```

Вторая клавиша — полный аппаратный power-off. Поэтому будильник может сработать только при оставленной включённой клавише.

Детальная силовая часть: `ПИТАНИЕ_И_ДВА_СВЕТИЛЬНИКА.md`.

## 4. ESP8266

ESP8266 — сетевой шлюз, а не контроллер эффектов.

Функции:

- Station в домашней сети как основной режим;
- SoftAP как резерв первичной настройки/восстановления;
- локальный HTTP API без облака;
- приём команд приложения;
- передача команд Nano по UART;
- возврат состояния/ответов Nano;
- восстановление Wi‑Fi независимо от Nano.

Белая adapter board питается только от **3,3 В**. На ней присутствует нулевой мост VCC→Module-VCC и нет установленного регулятора.

## 5. Arduino Nano

Nano выполняет:

- машину состояний;
- обработку MAX9814;
- VU/FHT/частотные алгоритмы;
- расчёт одного логического кадра и вывод его на два кольца;
- RTC и рассвет;
- хранение настроек;
- ограничение суммарного тока WS2812B;
- ответы ESP8266.

## 6. Два кольца WS2812B

Каждое кольцо имеет независимый DATA-вход от Nano. Это предпочтительнее одной последовательной цепочки через два потолочных корпуса.

Причины:

- обрыв DATA первого кольца не убивает второе;
- не требуется длинный DOUT→DIN переход между корпусами;
- одинаковое состояние задаётся программно;
- позже можно добавить режимы зеркала/симметрии без изменения проводки.

Предварительно: D6 → A, D7 → B.

Каждая DATA-линия должна иметь свой последовательный резистор около 330 Ом возле Nano.

## 7. Геометрия

Фактическая плотность по измерению владельца: около 60,7 LED/м.

Кантик: 71,5 см. Проектная цель: 43 LED на кольцо, 86 суммарно.

Окончательное число фиксируется только после физической укладки.

## 8. Бюджет питания

S-30-5 5 В 6 А сохраняется.

Из-за неизвестной ревизии WS2812B консервативный worst-case для 86 LED может доходить до 5,16 А только для лент. Поэтому прошивка должна ограничивать суммарный ток LED ориентировочно 4,5 А. Это допустимо, так как WS2812B не является основным белым освещением комнаты.

## 9. Аудиотракт

Основной микрофон MAX9814 остаётся на Nano, OUT → A0.

MAX4466 сохраняется только как резервный сравнительный вариант.

Один микрофон обслуживает оба синхронных светильника.

## 10. RTC

DS3231: SDA=A4, SCL=A5.

На конкретном модуле установлен CR2032 и присутствует зарядная цепь с `201` + диодом. Перед штатным питанием резистор `201` удалить, чтобы не заряжать CR2032.

## 11. UART и логические уровни

Аппаратный UART Nano D0/D1 используется для ESP8266.

- ESP TX 3,3 В → Nano RX;
- Nano TX 5 В → ESP RX только через делитель.

Кандидат делителя из наличия: 1,5 кОм сверху и 3,0 кОм снизу (два 1,5 кОм последовательно). Перед ESP измерить выход мультиметром.

## 12. Приложение и API

Мобильное приложение пишется заново. Старые команды Bluetooth не являются обязательным форматом.

Для первой версии выбран локальный HTTP API, потому что приложение передаёт команды режимов/параметров, а не аудиопоток в реальном времени. Это проще TCP-сессии/WebSocket и достаточно для светомузыки, которая вычисляется локально на Nano.

Набор режимов и структура API проектируются отдельным этапом.

## 13. Отказоустойчивость

При потере Wi‑Fi:

- текущий режим Nano продолжает работать;
- светомузыка не останавливается;
- RTC и будильник продолжают работать;
- ESP пытается восстановить Station или поднимает резервную SoftAP.

При аппаратном выключении второй клавиши весь ARDU обесточен; никакое программное восстановление невозможно до повторного включения питания.

## 14. Нерешённая физика монтажа

До финальной схемы 230 В/5 В нужно определить расстояние между корпусами, место разветвления существующей линии, число/сечение жил и безопасное место для S-30-5.
