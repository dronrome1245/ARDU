## 3. Подготовить компьютер до изменения железа

1. В PowerShell: `cd C:\ARDU` → `git switch main` → `git pull`.
2. До прошивки сохранить три текущих ответа (подставь фактический IP, если уже не 192.168.0.4):

   `curl.exe http://192.168.0.4/api/ping`  
   `curl.exe http://192.168.0.4/api/status`  
   `curl.exe http://192.168.0.4/api/settings`

   Должен отвечать работающий `ARDU_ESP_V1`, `uart_protocol=1`; на ESP должен быть доступен OTA через Station `8266`. Записать текущие сохранённые параметры и наличие/версию Nano.
3. Сохранить работающие ESP v1 / Nano v1 исходники/коммит отдельно как rollback. Старый `main` v1 — это не обязательно byte-identical копия прошивки, уже залитой в чип.
4. Пока текущий ESP доступен через роутер, **не отключать домашний Wi-Fi** и не пытаться тестировать ARDU-DIRECT. OTA старой ESP-прошивки работает только по домашней сети.

## 4. Подготовить ESP v2 к единственной OTA-загрузке

1. Из `05_WiFi_и_приложение/esp8266_ardu_v2/` скопировать `wifi_secrets.example.h` в **`wifi_secrets.h`**. Этот новый файл должен находиться рядом с `esp8266_ardu_v2.ino`, в той же директории.
2. В локальном `wifi_secrets.h` заменить:
   - `ARDU_WIFI_SSID` — точным названием уже работающей домашней Wi-Fi сети;
   - `ARDU_WIFI_PASSWORD` — её правильным паролем;
   - `ARDU_OTA_PASSWORD` — паролем, который необходимо прописать **в новую прошивку**. Для бесшовного обслуживания лучше оставить тот же, что использовался в работающей ESP v1. **Пароль, который Arduino IDE спрашивает при текущей OTA-загрузке, должен соответствовать старой, уже установленной прошивке**;
   - `ARDU_SOFTAP_PASSWORD` — новый уникальный пароль сети `ARDU-DIRECT`, минимум 8 символов.
3. Только после замены всех четырёх значений выставить `#define ARDU_CREDENTIALS_CONFIGURED 1`. В текущем ESP v2 обычная Arduino IDE сборка без локального файла и без этого флага **намеренно не скомпилируется**: защита от OTA с тестовыми/неверными ключами. `wifi_secrets.h` игнорируется Git. Секреты в чат не отправлять.
4. Arduino IDE: открыть `esp8266_ardu_v2.ino`, выбрать ту же проверенную плату **Generic ESP8266 Module** и Flash Size как при предыдущем рабочем OTA (по измерениям физического модуля flash 4 MB). Не менять пины GPIO0/RST/UART ради OTA. Сначала нажать **Verify**. Если `wifi_secrets.h` не найден / `ARDU_CREDENTIALS_CONFIGURED` не выставлен / есть compile error — исправить, не выполнять Upload.
5. В `Tools → Port` выбрать **сетевой** порт текущего `ardu` / IP работающего ESP, не COM порт Nano. Нажать **Upload** по OTA, при запросе использовать **старый установленный OTA пароль**. Если сетевой порт не виден, сначала проверить текущий `/api/ping` и рабочую сеть; не пытаться USB-OTA как замену.
6. После успешного Upload дождаться reboot и выполнить:

   `curl.exe http://192.168.0.4/api/ping`

   Ожидается `ok:true`, `fw:"ARDU_ESP_V2_AMBIENT12"`, `uart_protocol:1`, `wifi_connected:true`, `network_mode:"station"`, `ota_ready:true`. Прежняя Nano при этом ещё должна отвечать через `/api/status` и `/api/light/status`. В этом переходном состоянии `ambient_presets_supported:false` — **нормально**, Nano ещё не обновлена.
7. **STOP, если ESP не отвечает**: не трогать Nano. Проверить доступность Wi-Fi/адреса, текущий OTA пароль/SSID/фактическое питание ESP. Не выключать роутер и не считать SoftAP протестированным, пока не восстановлен Station-доступ.

## 5. Полная Nano v2 — только после ESP Station PASS

1. Открыть `04_Прошивка/nano_ambient12_v1/nano_ambient12_v1.ino` (вся прошивка, не самостоятельный demo sketch). Достаточно одного `.ino`, нужны установленные **FastLED** и та же оригинальная **FHT** из `04_Прошивка/libraries/FHT`.
2. Arduino IDE: Board **Arduino Nano**, Processor **ATmega328P (Old Bootloader)**, правильный физический COM-порт (USB-C Nano в текущем стенде).
3. **До перемещения проводов полностью выключить внешние 5 В и отсоединить USB.** Для программирования временно разъединить **ESP TX0/GPIO1 → Nano D0/RX**; делитель **Nano D1/TX → ESP RX** оставить. Не подавать на Nano USB 5 В и внешний +5 В одновременно без подтверждённой схемы развязки, не питать выключенную ленту через DATA. При неопределённости схемы остановиться до безопасного подключения.
4. Сначала **Verify**: при CI-зависимостях около `29306` Flash / `1282` SRAM globals. При flash overflow или иных error Upload запрещён.
5. Затем **Upload** полной Nano. Пока ESP TX ещё отсоединён, Serial Monitor **115200, Newline**:
   - `1` → `O 1`;
   - `2` → `D 2 ...`;
   - `4` → `D 4 ...` (валидное RTC, если синхронизировано);
   - `115` → `D 115 1 ...` с текущим выбранным P ID + 12 парами brightness/dynamics;
   - `111 3` → `O 111`, `115` показывает selected=3; `114` → `O 114` сохраняет выбор; `111 1` → `O 111` и `114` → `O 114`, чтобы продолжить тест первой сцены.
6. Закрыть Serial Monitor, **снять внешнее питание и USB**, затем вернуть провод **ESP TX0/GPIO1 → Nano D0/RX**. Включить стенд, проверить:

   `curl.exe http://192.168.0.4/api/status`  
   `curl.exe http://192.168.0.4/api/ambient/presets`  
   `curl.exe http://192.168.0.4/api/settings`

   Ожидание: `nano_fw:"ARDU_V2"`, `ambient_presets_supported:true`, `presets.supported:true`, все P01..P12 с параметрами. ESP по-прежнему должен обслуживать L01/Music/Night/Alarm. Не поднимать current limit >3000 mA до двухкольцевого power gate.
7. Если UART/LED неожиданно не работает, **не перепрошивать ESP повторно**. Проверь провод D0 и Nano Serial, при необходимости возврат к предыдущей полной Nano v1/стендовому release. Новая ESP v2 при старой Nano должна сохранять базовые функции.

## 6. Проверка 12 эффектов с компьютера и Android

HTTP-запрос примера (после установки обеих прошивок):

`Invoke-RestMethod "http://192.168.0.4/api/ambient/preset" -Method Post -ContentType "application/json" -Body '{"id":"P03"}'`

Тест индивидуальных настроек **активного** P03:

`Invoke-RestMethod "http://192.168.0.4/api/ambient/preset/settings" -Method Post -ContentType "application/json" -Body '{"brightness":102,"dynamics":120,"persist":true}'`

Повторный `GET /api/ambient/presets` должен подтвердить selected P03 + новые параметры P03; P01/P02 не должны измениться. Выбор F01 через старый `/api/ambient/effect {"id":"F01"}` возвращает ручной цвет. Запрос F02/F03 специально запрещён и не должен включать старые эффекты.

Затем Android Studio: `git pull` → открыть прежний `android_app_r1` → **Run**. Версия должна быть `0.22.6-ambient12-functional-rc1` (versionCode 29). Можно также скачать [проверенный debug APK](https://github.com/dronrome1245/ARDU/actions/runs/37819918951/artifacts/11568856875) и установить поверх старого приложения при том же ключе подписи (для CI debug keystore подпись может отличаться от локальной Android Studio). Если установка APK не проходит, использовать Android Studio Run.

В разделе «Фон» должны отображаться **F01 «Цвет» и 12 сцен, без F02/F03**, яркость и динамика выбранного пресета; после переключения сцены значение считывается из Nano, а не из памяти телефона. Внешний вид v0.22 Home Hub и ранее утверждённые hero-фоновые изображения сохранены. Четыре фото-превью сохранены; восемь остальных сцен пока имеют функциональные текстовые кнопки. Это **не** утверждённые фото для всех 12.

## 7. ARDU-DIRECT — физический тест БЕЗ роутера

**Только после успешной Station OTA + Nano + Android smoke.**

1. Оставь ARDU под питанием, но временно отключи именно домашний роутер/его Wi-Fi. Не выключай питание ARDU.
2. После потери Station ESP должен поднять защищённую сеть **`ARDU-DIRECT`**. На телефоне открой системные настройки Wi-Fi → `ARDU-DIRECT` → введи **свой** `ARDU_SOFTAP_PASSWORD`; подтверди соединение даже если Android пишет «Без доступа к Интернету».
3. Из приложения ARDU использовать прямой IP **`192.168.4.1`**. `GET http://192.168.4.1/api/ping` должен показать `network_mode:"softap"`, `wifi_connected:false`, `softap_active:true`. Проверь хотя бы L01 ON/OFF и переключение P01/P04.
4. OTA в direct/SoftAP **не запускать**: оно намеренно доступно только в Station. Верни домашнюю сеть: ESP должен снова подключиться к роутеру и отключить резервную точку доступа; приложение — вернуться к домашнему IP.
5. При неуспехе direct smoke — оставлять устройство в Station и диагностировать сеть; без подтверждения работы `ARDU-DIRECT` не объявлять продукт готовым к потолочному монтажу.

## 8. Полная приёмка перед словами «финальная прошивка»

Обязательно на **реальном** устройстве: один 44-LED канал → оба D6/D7, фактическое напряжение 5 В под нагрузкой, ток/температура/сечение и надёжность проводки, отсутствие LED glitches и UART corruption; L01 Kelvin/RGB/clap и калибровка MAX9814, Music M01/M02/M03/M04/M05/M08/M09, Night schedule, RTC/Alarm/Dawn/STOP/recovery, сохранение EEPROM через физический power-cycle, 12 реально различимых сцен, отдельные brightness/dynamics, Station→ARDU-DIRECT→Station, OTA доступ в Station.

**Пока не проверено:** SRAM stack worst-case, светодиодные сцены на железе, два кольца 44+44, защита/нагрев блока питания и прямой Wi-Fi. Nano занимает 29306 байт Flash (~96% > 95% project target), ESP IRAM 92%; оба компилируются, но это ещё не доказанный final hardware PASS. S-30-5 (металлический корпус без PE) пригоден только для стенда, для потолка нужен финальный Class II БП по BOM.

Если что-то не работает — зафиксировать результат конкретного gate и откатить **только** нарушенную подсистему; без серийных новых перепрошивок «на удачу».
