# Нейросеть: начни отсюда

Этот файл — обязательная точка входа для любой нейросети в новом чате по проекту ARDU.

## 1. Что это за проект

ARDU — проект круглой потолочной лампы с адресной лентой WS2812B, светомузыкой от микрофона, обычным светом/ночником, эффектами, будильником-рассветом и управлением со смартфона.

Исходная техническая база — ColorMusic AlexGyver, но проект адаптируется под фактически имеющиеся у владельца компоненты. Цель — не покупать новые платы без необходимости.

## 2. Главный принцип

Проектируем от реального наличия:

`инвентаризация → идентификация → проверка характеристик → архитектура → питание → распиновка → прошивка → управление → BOM → закупка только недостающего → стенд → интеграция в лампу`.

Нельзя формировать окончательный список покупок, пока не закончена инвентаризация и не проверена совместимость основных компонентов.

## 3. Что читать перед работой

В каждом новом чате читать в таком порядке:

1. `00_AI_START_HERE.md`;
2. `STATUS.md` — канонический текущий статус;
3. `DECISIONS.md` — принятые и заменённые решения;
4. `HISTORY.md` — фактически выполненные действия;
5. `SOURCES.md` — источники и фактические материалы;
6. `AGENTS.md` — постоянные правила;
7. `02_КОМПОНЕНТЫ_BOM.md` и `02_Наши_детали/ИНВЕНТАРЬ.md`, если задача связана с электроникой/закупками;
8. профильные файлы конкретной задачи.

Старые файлы `01_СТАТУС_ПРОЕКТА.md`, `02_СЛЕДУЮЩИЙ_ШАГ.md` и `03_СОСТОЯНИЕ_ПРОЕКТА.yaml` пока сохраняются для совместимости, но `STATUS.md` имеет приоритет как единый текущий статус.

## 4. Иерархия истины

При противоречии:

1. последнее явное решение владельца проекта;
2. `STATUS.md`;
3. более поздняя запись в `DECISIONS.md`;
4. актуальный профильный документ;
5. старые материалы, ранние схемы и прежние чаты.

Отменённые решения не удалять: помечать `ЗАМЕНЕНО` и сохранять причину.

## 5. После каждого существенного шага

До завершения ответа проверить необходимость обновления:

- `STATUS.md`;
- `DECISIONS.md`;
- `HISTORY.md`;
- `SOURCES.md`;
- `02_КОМПОНЕНТЫ_BOM.md`;
- `02_Наши_детали/ИНВЕНТАРЬ.md`.

Если изменился практический следующий шаг, синхронизировать также старые файлы handoff: `01_СТАТУС_ПРОЕКТА.md`, `02_СЛЕДУЮЩИЙ_ШАГ.md`, `03_СОСТОЯНИЕ_ПРОЕКТА.yaml`.

Нельзя писать «зафиксировано в проекте», если запись в GitHub фактически не выполнена при наличии доступа.

## 6. Факт, предположение и решение

Всегда различать:

- **ФАКТ** — читается с маркировки, подтверждён фото, измерением, документацией или исходным файлом;
- **ПРЕДПОЛОЖЕНИЕ** — вероятная идентификация/характеристика, требующая проверки;
- **РЕШЕНИЕ** — явно выбранный вариант проекта.

Если маркировка на фото читается не полностью, не придумывать номинал.

## 7. Технические решения

Любое существенное решение должно отвечать:

1. что выбрали;
2. почему;
3. чем подтверждено;
4. какие ограничения остаются;
5. что нужно проверить физически;
6. что это меняет в следующем шаге.

Для электроники проверять минимум:

- модель/маркировку;
- напряжение питания;
- допустимые логические уровни;
- ток/мощность;
- интерфейс;
- распиновку;
- совместимость с остальной схемой;
- необходимость развязки/стабилизатора/преобразователя уровней;
- пригодность для стенда и финальной лампы.

## 8. Текущая рабочая архитектура

До отдельного пересмотра рабочая схема:

`приложение → Wi‑Fi → ESP8266 → UART → Arduino Nano → MAX9814 / DS3231 / WS2812B`.

HC-05 сохраняется как резервный Bluetooth-канал для отладки.

Это рабочая архитектура, а не запрет на дальнейшее упрощение. Если инвентаризация покажет более удачный вариант из уже имеющихся деталей, он должен быть оформлен отдельным решением в `DECISIONS.md`.

## 9. Покупки

Статусы BOM:

- ✅ `ЕСТЬ` — подтверждено наличие;
- 🔵 `ПРОВЕРИТЬ` — вещь есть, но нужно подтвердить номинал/исправность/совместимость;
- 🟢 `ДОКУПИТЬ` — подтверждённо нужно для принятой архитектуры;
- 🟡 `ПОСЛЕ ИЗМЕРЕНИЙ/ТЕСТА` — покупать только после контрольного теста;
- ⚪ `ОПЦИОНАЛЬНО` — не требуется для базовой версии;
- ⛔ `НЕ НУЖНО ДЛЯ ARDU` — компонент может быть исправен, но в текущей архитектуре не нужен.

До окончания инвентаризации статус `🟢 ДОКУПИТЬ` назначать только очевидно обязательным и технически подтверждённым позициям.
