# 02 — СЛЕДУЮЩИЙ ШАГ

## Цель следующей итерации

Доказать, что имеющийся ESP8266MOD можно использовать как Wi‑Fi-шлюз проекта без покупки ESP32 и без вмешательства в работающую Nano-логику светомузыки.

## Последовательность

1. Зафиксировать фактическое питание переходной платы ESP8266MOD по маркировке/измерению и убедиться, что на VCC не подается недопустимое напряжение.
2. Определить доступный способ прошивки ESP8266.
3. Загрузить минимальный тест Wi‑Fi без ленты, микрофона и RTC.
4. Проверить один из режимов:
   - SoftAP для прямого подключения телефона; либо
   - Station для подключения к существующей сети.
5. После стабильного Wi‑Fi соединить UART ESP8266 ↔ Nano с согласованием уровня сигнала Nano TX → ESP8266 RX.
6. Передать тестовую строку `PING\n` и получить `PONG\n`.
7. Затем передать одну существующую команду приложения, например `L1\n`, и проверить, что Nano ее принимает через тот же парсер, который ранее работал с Bluetooth.

## Что не делать в этой итерации

- Не подключать сразу полную WS2812B нагрузку.
- Не переносить FHT/аудиоанализ на ESP8266.
- Не менять протокол приложения.
- Не удалять Bluetooth-код до успешной проверки Wi‑Fi тракта.
- Не подавать 5 В на VCC или RX ESP8266 без подтвержденной схемы конкретной переходной платы.

## Результат итерации

Результатом считается короткий тестовый контур:

`телефон/ПК → Wi‑Fi → ESP8266 → UART → Nano`

с подтвержденным двусторонним обменом командами.

После этого следующий этап — перенос транспорта мобильного приложения с Bluetooth на Wi‑Fi при сохранении существующих команд.
