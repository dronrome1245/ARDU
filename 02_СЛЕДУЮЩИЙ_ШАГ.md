# 02 — СЛЕДУЮЩИЙ ШАГ

> Совместимый handoff-файл. Канонический статус находится в `STATUS.md`.

## Цель следующей итерации

Подтвердить питание и физическую разводку двух потолочных корпусов, затем собрать первый ESP8266↔Nano стенд.

## Уже закрыто

- запас WS2812B подтверждён: 5 м;
- `Ardublock2.aia` разобран;
- режимы и параметры v1 определены;
- модель нового Wi‑Fi приложения определена;
- предварительный HTTP API создан.

## От владельца нужны три группы данных

1. Есть ли мультиметр и паяльник/припой.
2. Расстояние между двумя круглыми корпусами и фактическая потолочная проводка: где разветвляется линия второй клавиши, сколько жил приходит к каждому корпусу.
3. Где можно безопасно и обслуживаемо разместить общий S-30-5.

## Затем измерить

1. S-30-5: V+↔V- без нагрузки.
2. YP-8: 5 В на VIN → VOUT без нагрузки.
3. После подтверждения 3,3 В — YP-8 с ESP8266 под Wi‑Fi нагрузкой.
4. Прочитать маркировку и количество электролитов около `1000 µF`.
5. Собрать делитель Nano TX → ESP RX и измерить его выход до подключения ESP8266.

## Параллельная подготовка

- удалить `201` на DS3231 перед штатным питанием с CR2032;
- проверить способ прошивки ESP8266 через имеющийся Nano/другой мост;
- физически примерить 43 LED на кантик 71,5 см;
- не замыкать DOUT последнего LED обратно на DIN первого.

## После этого

1. утвердить окончательный BOM;
2. собрать `S-30-5 → Nano + YP-8/ESP8266 → UART → одно кольцо`;
3. добиться `PING/PONG`;
4. включить F01 постоянный цвет по Wi‑Fi;
5. добавить второе кольцо;
6. подключить MAX9814 и реализовать M01 VU градиент.

Подробный порядок: `04_Прошивка/ПОРЯДОК_РЕАЛИЗАЦИИ.md`.


## Актуальный следующий шаг 2026-09-20

Собрать безопасный низкоомный programmer-divider `750 Ом / 1,5 кОм` из имеющихся резисторов 1,5 кОм, оставить `100 µF 10 V` у ESP, проверить HIGH около 3,3 В и повторить upload на `115200` с ручным кратким `RST→GND` во время `Connecting...`. Прямой D0→ESP RX больше не использовать как штатный способ.


## Актуальный следующий шаг — FW-0 Nano

1. Полностью отделить Nano от ESP по D0/D1 на время загрузки FW-0.
2. Убрать перемычку `RESET Nano → GND` — она нужна была только когда Nano работала USB↔UART-мостом.
3. Оставить Nano подключённой только по USB к компьютеру и загрузить `04_Прошивка/nano_fw0/nano_fw0.ino`.
4. Открыть Serial Monitor `115200`, окончание строки `Newline`; ожидать `ARDU NANO FW0 READY`.
5. Отправить `PING` → ожидать `PONG`; затем `STATUS` → ожидать строку `STATUS FW=FW0 ...`.

До успешного теста кольцо, ESP и MAX9814 к FW-0 не подключать.


### Уточнение после первой попытки FW-0

Перед повторным Upload Nano: ESP должен быть полностью отключён от `D0` и `D1`; перемычка `RESET Nano→GND` снята; Serial Monitor закрыт. Повторить upload с текущими настройками Arduino IDE. Только если `not in sync` сохранится на полностью изолированной Nano, проверять вариант `ATmega328P (Old Bootloader)` и ручной reset.


### Следующий тест Nano после сохранения `resp=0x41`

В Arduino IDE выбрать `Tools → Processor → ATmega328P (Old Bootloader)` и повторить Upload при полностью свободных D0/D1 и снятом `RESET→GND`. Если ошибка сохранится — выполнить ручной reset Nano в момент начала загрузки.


## Актуальный следующий шаг — FW-1

FW-0 закрыт. Оставить Nano изолированной от ESP, выбрать `Arduino Nano → ATmega328P (Old Bootloader)`. Открыть `04_Прошивка/nano_fw1/nano_fw1.ino` и сначала выполнить только Verify/Compile. Если Arduino IDE сообщает, что `FastLED.h` не найден, установить библиотеку `FastLED` через Library Manager. Кольцо пока не подключать. После успешной компиляции перейти к физической схеме одного кольца на D6.


### FW-1 — физический тест одного канала

Собрать только Nano + один вход WS2812B: Nano питается по USB; лента питается от S-30-5 5 В; земли Nano и S-30-5/ленты объединены; `Nano 5V` с `S-30-5 V+` не соединять. DATA: D6 → DIN начала ленты; предпочтительно через 330 Ом, а для текущего короткого стенда допустим временный последовательный 1,5 кОм из наличия. Проверять первые 43 LED на малой яркости/лимите 500 мА. Второе кольцо, ESP и MAX9814 не подключать.


### FW-1 — схема по AlexGyver

Предыдущий временный вариант DATA через `1,5 кОм` отменён. Перед подключением ленты:
1. прочитать полную маркировку имеющегося электролита `1000 µF` и подтвердить рабочее напряжение ≥6,3 В;
2. найти среди имеющихся резистор `200–500 Ом` (предпочтительно 330 Ом) либо подтвердить, что его нет;
3. затем собрать: `S-30-5 +5V/GND → лента`, `1000 µF` параллельно +5V/GND у начала ленты, `Nano D6 → 200–500 Ом → DIN`, `Nano GND → GND ленты`. Nano остаётся на USB; Nano 5V к S-30-5 V+ не соединять.


### После подтверждения 1000 µF 6,3 V

Конденсатор для питания WS2812B подтверждён. Следующее — найти/подтвердить DATA-резистор `200–500 Ом` (целевой 330 Ом). До его подтверждения физический FW-1 с лентой не собирать.


### После подготовки 220 Ом

1. Пока лента не подключена, загрузить `04_Прошивка/nano_fw1/nano_fw1.ino` в Mini-USB Nano с `ATmega328P (Old Bootloader)`.
2. Отключить USB Nano и 230 В/S-30-5.
3. Собрать один канал: `Nano D6 → 220 Ом → DIN WS2812B`; `S-30-5 +5V → +5V ленты`; `S-30-5 V- → GND ленты`; `Nano GND → GND ленты`; `1000 µF 6,3 V` параллельно +5V/GND у начала ленты (`+` к +5V, `-` к GND).
4. `Nano 5V` с `S-30-5 +5V` не соединять. Второе кольцо, ESP и MAX9814 не подключать.
5. После сборки включить S-30-5, затем подключить Nano по USB. Ожидаемый результат — первые 43 LED тускло красные; затем проверить `STATUS`, `COLOR 0 32 0`, `COLOR 0 0 32`.


## Актуальный следующий шаг — FW-2

1. Открыть `04_Прошивка/nano_fw2/nano_fw2.ino`.
2. Оставить Mini-USB Nano как `Arduino Nano → ATmega328P (Old Bootloader)`.
3. Выполнить только Verify/Compile, не подключая второе кольцо.
4. После успешной компиляции подтвердить наличие второго DATA-резистора `200–500 Ом` (220 Ом подходит) и второго электролита около `1000 µF` ≥6,3 В для второго кольца либо временно тестировать два коротких сегмента рядом с одним общим качественным 5 В вводом.
5. Физический FW-2: D6→резистор→DIN A, D7→резистор→DIN B, обе ленты от S-30-5, общая GND, одинаковый кадр; затем команды `RING A`, `RING B`, `BOTH`.


## Актуальный шаг после решения о зеркальном D7

Второе кольцо пока не подключать. D7 физически не тестировать. На текущем D6-кольце завершить F01-команды:

1. `OFF` — все 43 LED должны погаснуть, ответ `OK`.
2. `ON` — должен вернуться текущий цвет, ответ `OK`.
3. `BRIGHT 8` — заметно уменьшить яркость, ответ `OK`.
4. `BRIGHT 64` — увеличить яркость, ответ `OK`.
5. `STATUS` — проверить, что POWER/BRIGHTNESS/RGB совпадают с командами.

После этого следующий физический слой добавлять только к одному кольцу. D7 остаётся зеркальным выходом и будет проверен после полной настройки первого кольца.


## Актуальный следующий шаг — MAX9814 на одном кольце

1. Сначала открыть и скомпилировать/загрузить `04_Прошивка/nano_mic_test/nano_mic_test.ino` на Mini-USB Nano (`ATmega328P (Old Bootloader)`).
2. После успешной загрузки обесточить стенд и подключить MAX9814: `Vdd→Nano 5V`, `GND→Nano GND`, `Out→A0`; `Gain` и `AR` оставить неподключёнными.
3. Включить стенд, Serial Monitor `115200`, `Newline`.
4. В тишине отправить `MIC` несколько раз; затем говорить/хлопать рядом с микрофоном и снова отправлять `MIC`.
5. Успех этапа: среднее значение остаётся в разумном диапазоне и `P2P` заметно увеличивается при звуке. Второе кольцо, ESP8266 и RTC пока не подключать.


### MAX9814 — уточнённый тест реакции на звук

Перезагрузить обновлённый `nano_mic_test.ino`. В Serial Monitor отправить `MIC1S` и в течение следующей секунды сохранять тишину; дождаться строки `MIC1S ...`. Затем снова отправить `MIC1S` и во время самой секунды сказать громко/хлопнуть рядом с микрофоном. Прислать обе строки. Сравниваем прежде всего `P2P`, а также MIN/MAX; только после этого решаем, годится ли текущая чувствительность MAX9814 для M01 без смены Gain/AREF.


### MAX9814 — уменьшить Gain до 50 dB

1. Обесточить Nano/стенд.
2. Соединить вывод `Gain` MAX9814 с `GND` MAX9814/Nano. `AR` оставить неподключённым.
3. Включить стенд; скетч менять не нужно.
4. Желательно выполнить тест с кольцом `OFF`, чтобы сначала измерить микрофон без возможной помехи от WS2812B.
5. Отправить `MIC1S` в тишине и ещё раз `MIC1S` с громкой речью/хлопком.
6. Цель: громкий тест не должен доходить до `MIN=0` или `MAX=1023`, а `P2P` должен заметно превышать тихий уровень. Если 50 dB всё ещё клиппует — следующий обратимый шаг `Gain→Vdd` (40 dB).


### MAX9814 — откат к последней рабочей схеме

1. Полностью выключить питание стенда.
2. Снять только перемычку `Gain→GND`.
3. Проверить, что остаётся ровно: `Vdd→5V`, `GND→GND`, `Out→A0`; `Gain` и `AR` свободны.
4. Включить и выполнить `MIC1S`.
5. Если `AVG` вернётся примерно к 250, модуль/ADC исправны; затем отдельно по маркировке платы повторно определить пин Gain. Если AVG останется около 0 — измерить мультиметром напряжение `Out→GND` на включённом модуле.


### MAX9814 — перед повторной сменой Gain

Не подключать Gain повторно вслепую. Сначала визуально подтвердить на конкретной плате подписи/расположение выводов `AR / Out / Gain / Vdd / GND` и место, куда ставилась перемычка. После подтверждения повторить 50 dB (`Gain→GND`) либо, если нужно больше запаса, 40 dB (`Gain→Vdd`). Floating 60 dB оставить только как диагностическое состояние: на громком сигнале уже наблюдается `MIN=0`.


### MAX9814 — повтор 50 dB после фотоидентификации

При выключенном питании соединить **центральный свободный** вывод `Gain` с **крайним правым** `GND` (куда приходит синий провод). Жёлтый `Out→A0` и зелёный `Vdd→5V` не трогать; `AR` оставить свободным. После включения выполнить `MIC1S` в тишине и при громком звуке.


### MAX9814 — следующий тест 40 dB

1. Полностью обесточить Nano/стенд.
2. Переставить перемычку `Gain`: снять с `GND` и соединить с `Vdd` MAX9814 (зелёный провод/пин Vdd). Не соединять Gain одновременно с GND и Vdd.
3. `Out→A0`, `Vdd→5V`, `GND→GND` оставить как есть; `AR` оставить свободным.
4. После включения выполнить `MIC1S` в тишине и `MIC1S` при громком звуке.
5. Цель: `MIN>0`, `MAX<1023`, при этом P2P громкого сигнала заметно выше тишины. Проверить также, что `SAMPLES` снова близко к ~5000; если снова около 1000, отдельно диагностировать частоту выборки.


### MAX9814 — перейти к 40 dB

1. Выключить питание.
2. Снять перемычку `Gain→GND`.
3. Соединить `Gain→Vdd` (центральный Gain на соседний справа Vdd/зелёный провод). `Out→A0`, `GND`, `AR` оставить как есть.
4. Включить и выполнить `MIC1S` в тишине.
5. Выполнить `MIC1S` при громкой речи/хлопке.
6. Успех: при громком звуке `MIN>0` и `MAX<1023`, а P2P заметно выше тихого. Тогда 40 dB принимаем для дальнейшего M01.


## Актуальный следующий шаг — M01 VU градиент

1. Оставить MAX9814: `Vdd→5V`, `GND→GND`, `Out→A0`, `Gain→Vdd` (40 dB), `AR` свободен. Второе кольцо и ESP не подключать.
2. Открыть `04_Прошивка/nano_m01/nano_m01.ino`, Verify/Compile и загрузить в Mini-USB Nano (`ATmega328P (Old Bootloader)`).
3. В тихой комнате отправить `CAL`; ожидать `CAL QUIET_MAX=... LOW_PASS=...`. Во время CAL не шуметь.
4. После CAL включить реальную музыку на обычной громкости. Кольцо должно давать симметричный VU-градиент от зелёного к красному и автоматически менять длину шкалы.
5. Для диагностики отправить `AUDIO`; прислать строку при тишине и при музыке, если визуально режим ведёт себя слишком тихо/слишком резко.
6. Экстремальный хлопок не использовать как основной критерий M01; частотные режимы/FHT позже отдельно проверят клиппинг и входную обработку.


## Актуальный следующий шаг — FHT diagnostic

1. Оставить текущее подключение MAX9814: `Gain→Vdd` (40 dB), `Out→A0`, `AR` floating; второе кольцо/ESP/RTC не подключать.
2. Открыть `04_Прошивка/nano_fht_test/nano_fht_test.ino` и выполнить Verify/Compile для `Arduino Nano → ATmega328P (Old Bootloader)`.
3. Если IDE сообщает `FHT.h: No such file or directory`, установить FHT-библиотеку из официального репозитория ColorMusic (`libraries/FHT`) и повторить Verify.
4. После успешной загрузки выполнить `CALF` в тишине.
5. Затем несколько раз `FREQ` в тишине и при музыке. Ожидается, что LOW/MID/HIGH меняются вместе со звуком, а после CALF тишина в основном подавлена.
6. На этом этапе лента специально гасится: сначала проверяем анализ, потом добавляем M03/M04.


### FHT — использовать AvrFHT

1. В Arduino IDE открыть Library Manager и установить `AvrFHT` by KobaProduction.
2. Открыть актуальный `04_Прошивка/nano_fht_test/nano_fht_test.ino` — он уже адаптирован под AvrFHT.
3. Verify/Compile для `Arduino Nano → ATmega328P (Old Bootloader)`.
4. После успешной загрузки: `CALF` в тишине, затем `FREQ` в тишине и при музыке.
5. Старую `FHT` из `AlexGyver/ColorMusic/libraries/FHT` отдельно копировать не нужно, если AvrFHT компилируется и проходит физический тест.


### AvrFHT — повтор после исправления DC-калибровки

1. Загрузить свежий `04_Прошивка/nano_fht_test/nano_fht_test.ino`.
2. Сначала отправить `ADC`. Нормальный ориентир для текущего MAX9814 — `AVG` примерно 240–270; MIN/MAX могут немного гулять.
3. Если `ADC AVG≈250`, отправить `CALF` в тишине. В строке `CALF DC=...` DC также должен быть около 250, а не 914.
4. Затем отправить `FREQRAW` в тишине и при музыке, после этого `FREQ`.
5. Если `ADC` снова показывает около 900, FHT пока не диагностировать: проверить физическое напряжение `OUT→GND` MAX9814 мультиметром.


### AvrFHT — один развилочный тест `ADC`

Не менять проводку и Gain. В текущем Serial Monitor отправить `ADC`.
- Если ответ `ERR UNKNOWN_COMMAND` — на Nano осталась предыдущая версия скетча; загрузить свежий `nano_fht_test.ino` и повторить `ADC`.
- Если `ADC AVG≈240..270` — железо MAX9814/A0 исправно, ошибка локализована в CALF/FHT-коде.
- Если `ADC AVG≈900..1000` — сначала измерить мультиметром `MAX9814 OUT→GND`; к FHT не переходить.


### 2026-09-21 — сначала восстановить обычный A0, FHT не трогать

1. Ничего не менять и отправить команду `ADC` в текущем FHT-скетче.
2. Если `ADC AVG` около 0: выключить питание, снять **только** перемычку `Gain→Vdd`, оставить `Out→A0`, `Vdd→5V`, `GND→GND`, `AR` свободным; включить и снова отправить `ADC`.
3. Если после снятия Gain `ADC AVG` возвращается примерно к 250 — проблема локализована в физической установке перемычки Gain/соседнем контакте. Не продолжать FHT до устойчивого прямого ADC.
4. Если и с floating Gain `ADC AVG≈0` — измерить мультиметром `MAX9814 OUT→GND` и проверить питание `Vdd→GND`.


### 2026-09-21 — перепрошить актуальный FHT-test

1. Не менять проводку MAX9814.
2. В Arduino IDE открыть заново файл `04_Прошивка/nano_fht_test/nano_fht_test.ino` из актуальной версии репозитория.
3. Выбрать `Arduino Nano → ATmega328P (Old Bootloader)` и Upload.
4. После старта отправить `HELP`; в ответе обязательно должна быть команда `ADC`.
5. Затем отправить `ADC` и прислать строку. Только после этого снова выполнять `CALF/FREQRAW`.


### 2026-09-21 — измерить MAX9814 напрямую мультиметром

Не менять прошивку и не выполнять CALF/FREQ. На включённом стенде измерить:
1. `красный щуп → Vdd MAX9814`, `чёрный → GND MAX9814`;
2. `красный щуп → Out MAX9814`, `чёрный → GND MAX9814`.

Ориентир: Vdd около 5 В; Out около 1,25 В DC. Если Out нормальный, проверить провод `Out→A0`/контакт A0. Если Out около 0 В, обесточить и проверить, не смещены ли разъёмы и не замыкает ли `Gain→Vdd` соседний `Out`.


### 2026-09-21 — проверить напряжение непосредственно на Nano A0

Не менять Gain, прошивку или FHT. Оставить `Out→A0` подключённым. На включённом стенде измерить мультиметром: красный щуп прямо на физический контакт `Nano A0`, чёрный щуп на `Nano GND`.
- Если `A0≈1,24 В` — провод до Nano исправен; далее проверять сам A0/ADC и скетч.
- Если `A0≈0 В` — неисправен/не попал в контакт провод `MAX9814 Out→A0` или разъём на одной из сторон.


### 2026-09-21 — прозвонить Out→A0

1. Полностью выключить питание Nano и MAX9814.
2. Снять сигнальный провод `MAX9814 Out→Nano A0` хотя бы с одного конца.
3. Прозвонить сам провод/джампер: сопротивление между его концами должно быть близко к 0 Ом.
4. При снятом Out измерить сопротивление `Nano A0→Nano GND`. Оно не должно быть близко к 0 Ом.
