# ARDU — Android app R1 transport test

Дата: 2026-09-29

## Цель

Проверить первый сквозной путь из native Android-приложения:

`Android phone → home Wi-Fi → ESP8266 HTTP BRIDGE R1 → UART → Nano FW10 CORE R1 → DS3231 → ответ в приложение`.

Этот тест не заменяет будущий semantic API и не подключает второе D7-кольцо.

## Проект

`05_WiFi_и_приложение/android_app_r1`

## Перед запуском

- Nano: FW10 CORE R1;
- ESP8266: HTTP BRIDGE R1;
- рабочий UART ESP↔Nano собран через проверенный divider Nano TX→ESP RX;
- DS3231 подключён и валиден;
- телефон находится в той же домашней Wi-Fi сети.

Если физический ESP ещё не перепрошивался после добавления startup UART framing fix, это не блокирует первый app launch, но fix нужно отдельно перенести на физический ESP перед окончательным regression.

## 1. Gradle Sync и запуск

1. Android Studio → **Open** → выбрать `05_WiFi_и_приложение/android_app_r1`.
2. Дождаться Gradle Sync без ошибок.
3. Если Android Studio предложит установить Android SDK 36, установить его.
4. Выбрать подключённый Android-телефон и нажать **Run**.

Норма: приложение открывается и автоматически начинает проверку связи.

## 2. `/api/ping`

Норма на основном экране:

- `Онлайн`;
- видна версия `HTTP_BRIDGE_R1`;
- IP/UART в обычном интерфейсе не показываются.

## 3. `/api/status`

В блоке состояния должен появиться raw ответ Nano, начинающийся примерно так:

`STATUS FW=FW10_CORE REV=1 ...`

Критично проверить конкретные поля:

- `FW=FW10_CORE`;
- `REV=1`;
- `LEDS=44`;
- `RING_A=D6`;
- `RING_B=DISCONNECTED_TEST`;
- `RTC_VALID=YES`.

## 4. `/api/time`

В поле времени ARDU должно появиться фактическое растущее время DS3231 в формате:

`YYYY-MM-DD HH:MM:SS`

Нажать **Обновить**, подождать несколько секунд и нажать ещё раз. Время должно увеличиться.

## 5. Developer Mode

1. Нажать **Developer Mode**.
2. В поле уже стоит `PING`.
3. Нажать **Отправить**.

Норма: ответ `PONG`.

Затем безопасно проверить:

- `TIME`;
- `LIGHT STATUS`;
- `CLAP STATUS`;
- `NIGHT STATUS`;
- `ALARM STATUS`;
- `DAWN STATUS`.

Ответы должны приходить без timeout/повреждённых строк.

## PASS

R1 transport PASS, если:

1. Gradle Sync проходит;
2. приложение устанавливается и запускается на физическом телефоне;
3. основной экран показывает Online;
4. `/api/status` возвращает FW10 CORE R1;
5. `/api/time` показывает валидное время DS3231;
6. Developer `PING` возвращает `PONG`;
7. несколько последовательных запросов не повреждают UART и не приводят к зависанию ESP/Nano.

После PASS следующий слой — пользовательский экран L01 и сквозной regression света через приложение по D-071.
