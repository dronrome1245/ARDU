# ARDU — Android app R1 transport test

Дата: 2026-09-29

## Цель

Проверить первый сквозной путь из native Android-приложения:

`Android phone → home Wi-Fi → ESP8266 HTTP BRIDGE R1 → UART → Nano FW10 CORE R1 → DS3231 → ответ в приложение`.

Этот тест не заменяет будущий semantic API и не подключает второе D7-кольцо.

## Проект

`05_WiFi_и_приложение/android_app_r1`

## Перед запуском

- Nano: FW10 CORE R1;
- ESP8266: HTTP BRIDGE R1;
- рабочий UART ESP↔Nano собран через проверенный divider Nano TX→ESP RX;
- DS3231 подключён и валиден;
- телефон находится в той же домашней Wi-Fi сети.

Если физический ESP ещё не перепрошивался после добавления startup UART framing fix, это не блокирует первый app launch, но fix нужно отдельно перенести на физический ESP перед окончательным regression.

## 1. Gradle Sync и запуск

1. Android Studio → **Open** → выбрать `05_WiFi_и_приложение/android_app_r1`.
2. Дождаться Gradle Sync без ошибок.
3. Если Android Studio предложит установить Android SDK 36, установить его.
4. Выбрать подключённый Android-телефон и нажать **Run**.

Норма: приложение открывается и автоматически начинает проверку связи.

## 2. `/api/ping`

Норма на основном экране:

- `Онлайн`;
- видна версия `HTTP_BRIDGE_R1`;
- IP/UART в обычном интерфейсе не показываются.

## 3. `/api/status`

В блоке состояния должен появиться raw ответ Nano, начинающийся примерно так:

`STATUS FW=FW10_CORE REV=1 ...`

Критично проверить конкретные поля:

- `FW=FW10_CORE`;
- `REV=1`;
- `LEDS=44`;
- `RING_A=D6`;
- `RING_B=DISCONNECTED_TEST`;
- `RTC_VALID=YES`.

## 4. `/api/time`

В поле времени ARDU должно появиться фактическое растущее время DS3231 в формате:

`YYYY-MM-DD HH:MM:SS`

Нажать **Обновить**, подождать несколько секунд и нажать ещё раз. Время должно увеличиться.

## 5. Developer Mode

1. Нажать **Developer Mode**.
2. В поле уже стоит `PING`.
3. Нажать **Отправить**.

Норма: ответ `PONG`.

Затем безопасно проверить:

- `TIME`;
- `LIGHT STATUS`;
- `CLAP STATUS`;
- `NIGHT STATUS`;
- `ALARM STATUS`;
- `DAWN STATUS`.

Ответы должны приходить без timeout/повреждённых строк.

## PASS

R1 transport PASS, если:

1. Gradle Sync проходит;
2. приложение устанавливается и запускается на физическом телефоне;
3. основной экран показывает Online;
4. `/api/status` возвращает FW10 CORE R1;
5. `/api/time` показывает валидное время DS3231;
6. Developer `PING` возвращает `PONG`;
7. несколько последовательных запросов не повреждают UART и не приводят к зависанию ESP/Nano.

После PASS следующий слой — пользовательский экран L01 и сквозной regression света через приложение по D-071.


## L01 semantic stage 1 — HTTP_BRIDGE_R5

После закрытия OTA gate приложение `0.3-l01-semantic-r1` должно использовать пользовательский semantic API физического `HTTP_BRIDGE_R5`, а не raw Developer endpoint.

### Read-only gate

1. `git pull`.
2. Открыть текущий `android_app_r1` в Android Studio.
3. Sync/build/install на физический телефон.
4. Запустить приложение в той же Wi-Fi сети.
5. Верх экрана: `Онлайн • HTTP_BRIDGE_R5`.
6. Блок L01 должен отобразить фактический профиль Nano, подтверждённый HTTP:
   - 2700 K;
   - brightness 64;
   - при текущем не-L01 режиме — `Выключен`.

PASS read-only означает, что Android успешно использует `GET /api/light/status`.

### ON/OFF gate

Только когда допустимо переключить текущий режим устройства:
1. нажать `Включить`;
2. D6 кольцо должно перейти в L01, приложение после reread показывает `Включён`;
3. нажать `Выключить`;
4. кольцо гаснет, приложение после reread показывает `Выключен`;
5. повторить несколько раз;
6. закрыть/открыть приложение и убедиться, что state перечитан из Nano;
7. Developer `PING` должен по-прежнему вернуть `PONG`.

До PASS этого gate не добавлять brightness/Kelvin/RGB/persistence.

## L01 stage 2 — brightness + Kelvin presets

Предусловия:
- L01 semantic read PASS;
- Android ON/OFF regression PASS;
- ESP обновлён OTA до `HTTP_BRIDGE_R6`.

Пакетный тест:
1. Запустить Android `0.4-l01-bright-kelvin-r1` и включить L01.
2. Перетащить brightness примерно на 32 → 128 → 220; после каждого отпускания slider приложение должно перечитать то же значение, а кольцо визуально менять яркость.
3. Нажать 2700 K → 4000 K → 6000 K; строка L01 должна показывать выбранный preset, а кольцо визуально переходить от тёплого к более холодному белому.
4. Вернуть 2700 K и brightness 64.
5. Нажать `Обновить`; состояние должно остаться 2700 K / 64.
6. Выполнить ON→OFF→ON; текущий RAM-профиль должен сохраниться.
7. Developer `PING` → `PONG`.

В этом gate не нажимать отдельный SAVE и не проверять power-cycle persistence: persistence — следующий слой.
