# Модель экранов мобильного приложения ARDU

Версия: 0.1  
Дата: 2026-09-06

## 1. Навигация

Вместо пяти отдельных Bluetooth-экранов старого LumpV3.1 делаем одно приложение с единым соединением и пятью рабочими разделами.

```text
Главная
├── Обычный свет
├── Светомузыка
├── Фон
├── Ночник
├── Будильник
└── Настройки
    └── Для разработчика
```

## 2. Главная

Показывает:

- связь: `Онлайн / Нет связи`;
- текущий раздел;
- программный ВКЛ/ВЫКЛ;
- пять крупных кнопок разделов;
- текущее время DS3231;
- если идёт рассвет — отдельную кнопку `Остановить рассвет`.

На главной не нужны технические данные вроде MAC/IP/HC-05.

## 2.1. Обычный свет

- ВКЛ/ВЫКЛ;
- яркость;
- режим `Температура / Цвет`;
- Kelvin slider;
- preset chips/buttons: 2700 K, 4000 K, 6000 K;
- color picker для произвольного RGB-цвета;
- `Сохранить как свет после включения питания`;
- хлопковый выключатель ВКЛ/ВЫКЛ;
- `Калибровать хлопки`;
- мастер калибровки: тишина → несколько пользователей/пар → тест результата → сохранить;
- индикатор текущего состояния хлопкового управления и статуса калибровки.

## 3. Светомузыка

Структура:

- ВКЛ/ВЫКЛ;
- выбор одного из режимов M01, M02, M03, M04, M05, M08, M09;
- при наличии — выбор подрежима;
- `Яркость эффекта`;
- `Фоновая яркость`;
- динамические параметры режима;
- `Калибровка микрофона`.

Пример динамики:

- M01: показывать `Плавность`;
- M02: `Плавность`, `Скорость радуги`;
- M03/M04: `Плавность`, `Чувствительность`;
- M05: `Подрежим`, `Плавность`, `Чувствительность`;
- M08: `Подрежим`, `Скорость`, `Чувствительность`;
- M09: `Шаг цвета`, `Цвет`.

## 4. Фон

- ВКЛ/ВЫКЛ;
- F01 Постоянный цвет;
- F02 Плавная смена цвета;
- F03 Бегущая радуга;
- параметры текущего эффекта;
- автоперебор;
- период автоперебора.

## 5. Ночник

- ВКЛ/ВЫКЛ;
- цвет;
- насыщенность;
- яркость;
- расписание ВКЛ/ВЫКЛ — штатная функция NIGHT R2.

## 6. Будильник

- ВКЛ/ВЫКЛ;
- время;
- длительность рассвета;
- максимальная яркость;
- начальный цвет;
- конечный цвет;
- синхронизация RTC с телефоном;
- состояние RTC;
- текущее время DS3231;
- `Остановить рассвет`.

## 7. Настройки

Обычные:

- имя лампы;
- Wi‑Fi;
- переподключение/первичная настройка;
- версия.

Сервисные:

- тест кольца A;
- тест кольца B;
- тест микрофона;
- состояние RTC;
- состояние Nano;
- диагностика ESP8266.

## 7.1. Для разработчика

Отдельный экран Developer Mode:

- System status: Nano/ESP/RTC/MAX9814, версии и текущий режим;
- Microphone diagnostics: ADC, DC, DC_OK, calibration/noise threshold, bands;
- LED/mode tests;
- RTC/Alarm/Dawn/Night diagnostics;
- live monitor;
- поле ручной сервисной команды + SEND;
- полный текстовый ответ Nano;
- опасные действия требуют дополнительного подтверждения.

Обычная настройка каждого режима и кнопка калибровки микрофона остаются на пользовательских экранах; Developer Mode нужен для тестов и диагностики.

## 8. Правило UX

Приложение всегда сначала читает состояние лампы и полный набор сохранённых настроек всех режимов, затем рисует интерфейс. Локальный cache телефона нужен для удобства, но после подключения не считается источником истины.

## 13. FINAL Android v1 direction — Home Hub + Focus Dial (2026-10-03)

Owner-approved final direction.

### Свет / обзор — Home Hub

Entry point of the Light tab:
- contextual living-room hero;
- current ordinary-light device summary;
- quick scenes;
- brightness summary;
- Kelvin summary;
- device card opens detailed control.

### Свет / управление — Focus Dial

Detailed control:
- back to Home Hub overview;
- large circular 270° brightness dial;
- +/- and ON/OFF;
- semantic Kelvin smart slider;
- color wheel;
- optional exact RGB;
- startup profile;
- clap enable/calibration.

Focus Dial uses 0..255 internally and displays percent. During touch it previews locally; on release it writes via the existing Light semantic endpoint and then state is reread.

### Context heroes

The same Home Hub visual language appears at the top of:
- Music — music-room context;
- Ambient — colored ambient context;
- Night — bedroom/night context;
- Alarm/Dawn — dawn bedroom context.

Implementation is native Canvas rendering (`RoomHeroView`), not external images.

### Contract rule

Home Hub and Focus Dial do not define new device modes. They are presentation/composition over the already frozen HTTP API v1 and Nano UART v1.

## 16. Context photo hero propagation — v0.18

После owner-phone PASS исправленного Light v0.17 начат следующий предусмотренный D-087 visual pass.

Music / Ambient / Night / Alarm сохраняют существующую структуру и semantic controls, но их `RoomHeroView` теперь использует real-photo bitmap rendering вместо схематичной Canvas-комнаты.

Текущая безопасная итерация использует утверждённый Light `ardu_light_hero.webp` как общий 640×360 high-resolution master с разной композицией:
- Music: focus ≈ X 0.28 / Y 0.48, indigo + teal light grade;
- Ambient: focus ≈ X 0.52 / Y 0.50, purple + cyan grade;
- Night: focus ≈ X 0.72 / Y 0.50, deep navy + warm lamp;
- Alarm/Dawn: focus ≈ X 0.60 / Y 0.48, warm sunrise/golden grade.

Цель этой итерации — сначала проверить на реальном телефоне crop, readable contrast и место hero в четырёх уже работающих экранах. После PASS общий master может быть заменён на отдельные generated WebP для music-room / ambient-room / night-bedroom / dawn-bedroom без изменения view/API contract.

Таким образом фраза раздела 13 про native Canvas rendering относится к исходной реализации v0.14 и больше не описывает текущий фон contextual heroes. Native Android view остаётся контейнером/рендерером; HTTP API v1 и Nano UART v1 неизменны.
