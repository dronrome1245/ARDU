# Модель экранов мобильного приложения ARDU

Версия: 0.1  
Дата: 2026-09-06

## 1. Навигация

Вместо пяти отдельных Bluetooth-экранов старого LumpV3.1 делаем одно приложение с единым соединением и пятью рабочими разделами.

```text
Главная
├── Обычный свет
├── Светомузыка
├── Фон
├── Ночник
├── Будильник
└── Настройки
    └── Для разработчика
```

## 2. Главная

Показывает:

- связь: `Онлайн / Нет связи`;
- текущий раздел;
- программный ВКЛ/ВЫКЛ;
- пять крупных кнопок разделов;
- текущее время DS3231;
- если идёт рассвет — отдельную кнопку `Остановить рассвет`.

На главной не нужны технические данные вроде MAC/IP/HC-05.

## 2.1. Обычный свет

- ВКЛ/ВЫКЛ;
- яркость;
- режим `Температура / Цвет`;
- Kelvin slider;
- preset chips/buttons: 2700 K, 4000 K, 6000 K;
- color picker для произвольного RGB-цвета;
- `Сохранить как свет после включения питания`;
- хлопковый выключатель ВКЛ/ВЫКЛ;
- `Калибровать хлопки`;
- мастер калибровки: тишина → несколько пользователей/пар → тест результата → сохранить;
- индикатор текущего состояния хлопкового управления и статуса калибровки.

## 3. Светомузыка

Структура:

- ВКЛ/ВЫКЛ;
- выбор одного из режимов M01, M02, M03, M04, M05, M08, M09;
- при наличии — выбор подрежима;
- `Яркость эффекта`;
- `Фоновая яркость`;
- динамические параметры режима;
- `Калибровка микрофона`.

Пример динамики:

- M01: показывать `Плавность`;
- M02: `Плавность`, `Скорость радуги`;
- M03/M04: `Плавность`, `Чувствительность`;
- M05: `Подрежим`, `Плавность`, `Чувствительность`;
- M08: `Подрежим`, `Скорость`, `Чувствительность`;
- M09: `Шаг цвета`, `Цвет`.

## 4. Фон

- ВКЛ/ВЫКЛ;
- F01 Постоянный цвет;
- F02 Плавная смена цвета;
- F03 Бегущая радуга;
- параметры текущего эффекта;
- автоперебор;
- период автоперебора.

## 5. Ночник

- ВКЛ/ВЫКЛ;
- цвет;
- насыщенность;
- яркость;
- расписание ВКЛ/ВЫКЛ — штатная функция NIGHT R2.

## 6. Будильник

- ВКЛ/ВЫКЛ;
- время;
- длительность рассвета;
- максимальная яркость;
- начальный цвет;
- конечный цвет;
- синхронизация RTC с телефоном;
- состояние RTC;
- текущее время DS3231;
- `Остановить рассвет`.

## 7. Настройки

Обычные:

- имя лампы;
- Wi‑Fi;
- переподключение/первичная настройка;
- версия.

Сервисные:

- тест кольца A;
- тест кольца B;
- тест микрофона;
- состояние RTC;
- состояние Nano;
- диагностика ESP8266.

## 7.1. Для разработчика

Отдельный экран Developer Mode:

- System status: Nano/ESP/RTC/MAX9814, версии и текущий режим;
- Microphone diagnostics: ADC, DC, DC_OK, calibration/noise threshold, bands;
- LED/mode tests;
- RTC/Alarm/Dawn/Night diagnostics;
- live monitor;
- поле ручной сервисной команды + SEND;
- полный текстовый ответ Nano;
- опасные действия требуют дополнительного подтверждения.

Обычная настройка каждого режима и кнопка калибровки микрофона остаются на пользовательских экранах; Developer Mode нужен для тестов и диагностики.

## 8. Правило UX

Приложение всегда сначала читает состояние лампы и полный набор сохранённых настроек всех режимов, затем рисует интерфейс. Локальный cache телефона нужен для удобства, но после подключения не считается источником истины.


## 9. Реализованная навигация v1 — 2026-10-02

Для Android `0.10-design-v1-rc1` модель уточнена:

- верхняя карточка всегда показывает ARDU, Online/Offline, текущий режим и время DS3231;
- `Настройки` открываются отдельной кнопкой в верхней карточке;
- пять пользовательских разделов закреплены в нижней навигации:
  - Свет;
  - Музыка;
  - Фон;
  - Ночь;
  - Будильник;
- нижняя навигация не прокручивается горизонтально;
- содержимое выбранного раздела прокручивается вертикально;
- настройки внутри разделов сгруппированы в смысловые карточки;
- цветовые параметры получают локальное preview-поле;
- Developer Mode находится только внутри Settings.

Визуальная тема v1 — тёмная, с низкой яркостью фона и бирюзовым accent; это не влияет на логику режимов и API.


## 10. Smart-home UI pass — Light screen v0.11

После owner review v0.10 экран Light используется как pilot нового interaction language.

### Compact header

Everyday header now contains only:
- ARDU;
- Online/Offline;
- current semantic mode;
- RTC HH:MM;
- compact Refresh;
- compact Settings.

Firmware/RSSI/uptime remain available in Settings diagnostics.

### Light primary controls

Primary interaction order:
1. current power/state;
2. quick scenes;
3. brightness percent with +/- step actions;
4. white temperature;
5. touch color wheel;
6. behavior/startup/clap.

Precise RGB sliders are hidden by default under `Точная RGB настройка`.

Quick scenes currently:
- Evening: 2200 K / ~30%;
- Warm: 2700 K / ~70%;
- Day: 4000 K / ~80%;
- Cool: 6000 K / ~80%.

These scenes are app-side compositions of existing Light semantic writes and are not stored as new Nano modes.

Rule for next design work: replicate this interaction language to Music/Ambient/Night/Alarm only after owner approves the Light pilot.


## 11. Smart slider language — v0.12

Primary Light continuous controls no longer use stock Android SeekBar.

- Brightness: thick rounded semantic fill + large thumb.
- White temperature: warm orange → white → cool blue gradient.
- Touch anywhere on the track changes the preview.
- HTTP write occurs on touch release, not for every movement.
- +/- and quick scenes remain as fast discrete alternatives.

This `SmartSliderView` is the reusable UI primitive intended for later Music/Ambient/Night/Alarm polish after owner review.
