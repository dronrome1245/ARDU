# Функциональная модель нового приложения ARDU

Версия: 0.1  
Дата: 2026-09-06

## 1. Цель

Новое приложение создаётся заново. Старый App Inventor проект используется только как источник функций и UX-идей.

Основная схема:

`телефон → домашний Wi‑Fi → ESP8266 → UART → Nano`

ARDU v1 использует домашнюю локальную Wi-Fi сеть как основной Station transport. По решению владельца 2026-10-05 при недоступном роутере ESP8266 поднимает защищённый fallback SoftAP `ARDU-DIRECT`; direct IP = `192.168.4.1`. Интернет для обоих вариантов не требуется.

Доступ в Интернет для управления не требуется: HTTP-сервер работает локально на ESP8266. Облако для базовой версии не требуется.

---

## 2. Главный экран

На главном экране оставить текущее состояние и пять разделов:

- **Обычный свет**;
- **Светомузыка**;
- **Фон**;
- **Ночник**;
- **Будильник**.

Также показывать:

- состояние связи с лампой;
- текущее время DS3231; источником истины для отображаемого времени является RTC лампы, а не часы телефона;
- текущий режим;
- программный ВКЛ/ВЫКЛ всей декоративной подсветки;
- сервисную кнопку настроек.

Не показывать пользователю Bluetooth, IP-адрес и технические UART-команды в обычном режиме.

---

## 2.1. Экран «Обычный свет»

- ВКЛ/ВЫКЛ L01;
- яркость;
- переключение способа выбора цвета: `Температура` / `Цвет`;
- Kelvin slider;
- быстрые preset-кнопки: `2700 K`, `4000 K`, `6000 K`;
- color picker для любого цвета, включая красный/синий/зелёный и т. д.;
- состояние хлопкового выключателя;
- включение/отключение хлопкового выключателя;
- фактическое состояние, прочитанное с Nano;
- действие `Сохранить как обычный свет при включении питания`.

После cold power-on от подачи 230 В L01 включается с последним сохранённым startup profile: mode + Kelvin/RGB + brightness.

Kelvin на WS2812B является приблизительной визуальной имитацией, а не колориметрически гарантированной температурой.

---

## 3. Экран «Светомузыка»

Состав:

1. переключатель ВКЛ/ВЫКЛ;
2. выбор одного из музыкальных режимов;
3. подрежим — только если он есть у выбранного режима;
4. яркость активных LED;
5. яркость фона;
6. параметры №1/№2 с нормальными названиями, а не стрелками;
7. чувствительность — где применима;
8. кнопка `Калибровка микрофона`;
9. индикатор уровня звука — добавить позднее, если не создаёт лишнюю нагрузку на сеть.

Приложение не должно показывать неработающие настройки для текущего режима.

---

## 4. Экран «Фон»

Минимальный набор:

- ВКЛ/ВЫКЛ;
- выбор эффекта;
- цвет/насыщенность/яркость для применимых эффектов;
- скорость;
- шаг радуги;
- следующий/предыдущий эффект;
- автоперебор;
- период автоперебора.

Базовые эффекты v1:

- постоянный цвет;
- плавная смена цвета;
- бегущая радуга.

---

## 5. Экран «Ночник»

Минимальный набор:

- ВКЛ/ВЫКЛ;
- цвет;
- насыщенность;
- яркость;
- расписание ВКЛ/ВЫКЛ — включено в FW-9 NIGHT R2; поддерживается интервал через полночь.

Параметр Kelvin не использовать как основной, потому что WS2812B — RGB, а не CCT-лента.

---

## 6. Экран «Будильник»

Состав:

- будильник ВКЛ/ВЫКЛ;
- время;
- длительность рассвета;
- максимальная яркость;
- начальный цвет;
- конечный цвет;
- кнопка `Остановить текущий рассвет`;
- состояние RTC;
- кнопка `Синхронизировать время с телефоном`.

Будильник и рассвет должны после настройки работать автономно, без телефона и без Wi‑Fi.

Физическое ограничение: вторая клавиша настенного выключателя должна оставаться включённой, иначе питание снято полностью.

---

## 7. Экран «Настройки»

Пользовательские настройки:

- домашняя Wi‑Fi сеть;
- имя устройства;
- восстановление соединения;
- сброс сетевых настроек;
- версия прошивки.

Сервисные/диагностические пункты можно скрыть в отдельном разделе:

- состояние Nano;
- состояние RTC;
- состояние микрофона;
- тест кольца A;
- тест кольца B;
- текущий программный лимит тока;
- журнал последней ошибки.

---

## 7.1. Режим разработчика

В приложении обязателен отдельный Developer Mode. Он не заменяет обычный пользовательский UI.

Функции:

- полный STATUS Nano/ESP/RTC/MAX9814;
- запуск тестов режимов;
- просмотр диагностических значений ADC/DC/noise threshold/bands;
- live monitor диагностических параметров;
- отправка сервисных/тестовых команд через ESP8266→UART→Nano;
- отображение полного ответа Nano, включая `OK`, `ERR` и асинхронные `EVENT`;
- опасные сервисные действия отделять от обычных настроек и требовать явного подтверждения.

Все обычные параметры каждого режима должны настраиваться в штатном экране режима, а не только через Developer Mode.

Калибровка MAX9814 является штатной функцией экрана «Светомузыка» и запускается из приложения.

---

## 8. Сетевой API v1

Старый Bluetooth-протокол не переносить наружу. ESP8266 предоставляет понятный локальный HTTP API, а внутри преобразует запросы в компактные UART-команды Nano.

Предварительный набор HTTP методов:

### Состояние

- `GET /api/status` — общее состояние;
- `GET /api/settings` — текущие настройки;
- `GET /api/time` — время RTC.

### Управление режимом

- `POST /api/mode` — выбрать раздел/режим;
- `POST /api/power` — программный ВКЛ/ВЫКЛ.

### Светомузыка

- `POST /api/music/mode`;
- `POST /api/music/settings`;
- `POST /api/music/calibrate`.

### Фон

- `POST /api/ambient/effect`;
- `POST /api/ambient/settings`.

### Ночник

- `POST /api/night/settings`.

### Будильник

- `POST /api/alarm/settings`;
- `POST /api/alarm/stop-dawn`;
- `POST /api/time/sync`.

Точные JSON-поля зафиксировать после утверждения модели данных Nano.

---

## 8.1. Сохранение настроек

- каждый режим имеет собственный сохранённый набор параметров;
- приложение сохраняет локальный cache для удобства, но Nano является каноническим хранилищем;
- после полной потери питания параметры режимов должны сохраниться;
- изменения slider могут передаваться как live preview без записи каждого промежуточного значения в EEPROM;
- финальное значение после завершения редактирования должно получить подтверждение persistent save от Nano;
- при открытии приложения значения перечитываются с устройства, поэтому настройки доступны и с другого телефона.

## 9. Принципы связи

- приложение не должно знать о пинах Nano;
- приложение не должно знать о формате FHT;
- отображаемое системное время ARDU берётся из DS3231 через ESP8266; телефонное время используется только при явной команде синхронизации;
- ESP8266 не должен сам генерировать музыкальные эффекты;
- Nano остаётся источником истины по текущему режиму и настройкам света;
- Nano энергонезависимо хранит пользовательские настройки всех режимов;
- приложение хранит локальный cache всех настроек для UI, но после подключения обязательно синхронизирует его с Nano;
- после открытия приложения оно сначала запрашивает текущее состояние и полный набор сохранённых настроек устройства, а не считает локальный cache истинным;
- команды изменения настроек должны получать подтверждение применения;
- при потере Wi‑Fi лампа продолжает выполнять текущий режим и будильник автономно.

---

## 10. Что использовать из старого App Inventor

Полезные идеи:

- крупные отдельные функциональные разделы;
- понятные бегунки яркости;
- калибровка микрофона отдельной кнопкой;
- отдельная настройка будильника;
- отображение названия текущего музыкального режима.

Что исправляем:

- единое соединение вместо Bluetooth на каждом экране;
- нормальные названия параметров вместо кнопок `< > + -`;
- текущее состояние загружается из устройства;
- неподходящие настройки скрываются;
- общий дизайн упрощается под два одинаковых синхронных кольца.

## 11. Порядок реализации приложения

**Условие старта (обновлено 2026-09-27):** по решению владельца повторный общий ручной regression Nano перенесён на сквозной тест через приложение. До Android app требуется только рабочий Nano integration baseline и минимально проверенный ESP8266 HTTP↔UART transport.

После этого:

1. подключение к ESP8266, `GET /api/status` и `GET /api/settings`;
2. постоянный цвет и программный ON/OFF;
3. экран светомузыки + M01;
4. калибровка микрофона;
5. остальные музыкальные режимы;
6. будильник/RTC;
7. фон;
8. ночник;
9. сервисные функции и улучшение UX.

Приложение разрабатывается параллельно с финализацией интеграционной Nano-прошивки после минимального pass транспортного слоя ESP. Сквозной regression через приложение является частью финализации Nano/API.


### Калибровка хлопкового выключателя

На экране «Обычный свет» должна быть пользовательская кнопка `Калибровать хлопки`.

Wizard:
1. попросить обеспечить тишину;
2. приложение запускает quiet baseline;
3. выбрать/указать количество пользователей либо просто число calibration pairs;
4. рекомендованный сценарий для трёх детей: каждый делает 3 double-clap pair;
5. приложение показывает прогресс успешных sample;
6. Nano рассчитывает suggested threshold;
7. пользователь тестирует double clap;
8. `Сохранить` коммитит threshold в Nano EEPROM;
9. `Отмена` восстанавливает предыдущую настройку.

Приложение не вычисляет detector threshold самостоятельно — источником расчёта и истины остаётся Nano.

### Router-less fallback — 2026-10-05

- primary: Station в домашней LAN;
- fallback: WPA2 SoftAP `ARDU-DIRECT`, `192.168.4.1`;
- отдельный SoftAP password задаётся локально перед сборкой ESP и не коммитится;
- HTTP API одинаков в обоих режимах;
- OTA разрешён только в Station;
- Android probe list включает direct IP;
- если телефон ещё не подключён к `ARDU-DIRECT`, Android использует системное Wi-Fi подключение/подтверждение пользователя; Интернет не требуется.

### Выбор активных колец — 2026-10-05

- system-level selection: `A`, `B`, `BOTH`;
- normal profile and emergency profile are stored separately on Nano;
- defaults: normal=`BOTH`, emergency=`A`;
- D8 MAINS_SENSE automatically chooses which profile is active;
- selection applies to Light, Music, Ambient, Night and Dawn;
- inactive ring receives a black WS2812 frame; v1 does not physically disconnect its +5 V;
- Android Settings exposes both profiles and shows current active selection/power source.
