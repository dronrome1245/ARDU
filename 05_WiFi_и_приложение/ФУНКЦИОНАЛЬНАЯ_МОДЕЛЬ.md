# Функциональная модель нового приложения ARDU

Версия: 0.1  
Дата: 2026-09-06

## 1. Цель

Новое приложение создаётся заново. Старый App Inventor проект используется только как источник функций и UX-идей.

Основная схема:

`телефон → домашний Wi‑Fi → ESP8266 → UART → Nano`

Резервный режим настройки:

`телефон → SoftAP ESP8266`

Облако для базовой версии не требуется.

---

## 2. Главный экран

На главном экране оставить только текущее состояние и четыре раздела:

- **Светомузыка**;
- **Фон**;
- **Ночник**;
- **Будильник**.

Также показывать:

- состояние связи с лампой;
- текущий режим;
- программный ВКЛ/ВЫКЛ всей декоративной подсветки;
- сервисную кнопку настроек.

Не показывать пользователю Bluetooth, IP-адрес и технические UART-команды в обычном режиме.

---

## 3. Экран «Светомузыка»

Состав:

1. переключатель ВКЛ/ВЫКЛ;
2. выбор одного из музыкальных режимов;
3. подрежим — только если он есть у выбранного режима;
4. яркость активных LED;
5. яркость фона;
6. параметры №1/№2 с нормальными названиями, а не стрелками;
7. чувствительность — где применима;
8. кнопка `Калибровка микрофона`;
9. индикатор уровня звука — добавить позднее, если не создаёт лишнюю нагрузку на сеть.

Приложение не должно показывать неработающие настройки для текущего режима.

---

## 4. Экран «Фон»

Минимальный набор:

- ВКЛ/ВЫКЛ;
- выбор эффекта;
- цвет/насыщенность/яркость для применимых эффектов;
- скорость;
- шаг радуги;
- следующий/предыдущий эффект;
- автоперебор;
- период автоперебора.

Базовые эффекты v1:

- постоянный цвет;
- плавная смена цвета;
- бегущая радуга.

---

## 5. Экран «Ночник»

Минимальный набор:

- ВКЛ/ВЫКЛ;
- цвет;
- насыщенность;
- яркость;
- расписание ВКЛ/ВЫКЛ — как дополнительная функция после основной реализации.

Параметр Kelvin не использовать как основной, потому что WS2812B — RGB, а не CCT-лента.

---

## 6. Экран «Будильник»

Состав:

- будильник ВКЛ/ВЫКЛ;
- время;
- длительность рассвета;
- максимальная яркость;
- начальный цвет;
- конечный цвет;
- кнопка `Остановить текущий рассвет`;
- состояние RTC;
- кнопка `Синхронизировать время с телефоном`.

Будильник и рассвет должны после настройки работать автономно, без телефона и без Wi‑Fi.

Физическое ограничение: вторая клавиша настенного выключателя должна оставаться включённой, иначе питание снято полностью.

---

## 7. Экран «Настройки»

Пользовательские настройки:

- домашняя Wi‑Fi сеть;
- имя устройства;
- восстановление соединения;
- сброс сетевых настроек;
- версия прошивки.

Сервисные/диагностические пункты можно скрыть в отдельном разделе:

- состояние Nano;
- состояние RTC;
- состояние микрофона;
- тест кольца A;
- тест кольца B;
- текущий программный лимит тока;
- журнал последней ошибки.

---

## 8. Сетевой API v1

Старый Bluetooth-протокол не переносить наружу. ESP8266 предоставляет понятный локальный HTTP API, а внутри преобразует запросы в компактные UART-команды Nano.

Предварительный набор HTTP методов:

### Состояние

- `GET /api/status` — общее состояние;
- `GET /api/settings` — текущие настройки;
- `GET /api/time` — время RTC.

### Управление режимом

- `POST /api/mode` — выбрать раздел/режим;
- `POST /api/power` — программный ВКЛ/ВЫКЛ.

### Светомузыка

- `POST /api/music/mode`;
- `POST /api/music/settings`;
- `POST /api/music/calibrate`.

### Фон

- `POST /api/ambient/effect`;
- `POST /api/ambient/settings`.

### Ночник

- `POST /api/night/settings`.

### Будильник

- `POST /api/alarm/settings`;
- `POST /api/alarm/stop-dawn`;
- `POST /api/time/sync`.

Точные JSON-поля зафиксировать после утверждения модели данных Nano.

---

## 9. Принципы связи

- приложение не должно знать о пинах Nano;
- приложение не должно знать о формате FHT;
- ESP8266 не должен сам генерировать музыкальные эффекты;
- Nano остаётся источником истины по текущему режиму и настройкам света;
- после открытия приложения оно сначала запрашивает текущее состояние устройства, а не считает локально сохранённые значения истинными;
- команды изменения настроек должны получать подтверждение применения;
- при потере Wi‑Fi лампа продолжает выполнять текущий режим и будильник автономно.

---

## 10. Что использовать из старого App Inventor

Полезные идеи:

- крупные отдельные функциональные разделы;
- понятные бегунки яркости;
- калибровка микрофона отдельной кнопкой;
- отдельная настройка будильника;
- отображение названия текущего музыкального режима.

Что исправляем:

- единое соединение вместо Bluetooth на каждом экране;
- нормальные названия параметров вместо кнопок `< > + -`;
- текущее состояние загружается из устройства;
- неподходящие настройки скрываются;
- общий дизайн упрощается под два одинаковых синхронных кольца.

---

## 11. Порядок реализации приложения

1. подключение к ESP8266 и `GET /api/status`;
2. постоянный цвет и программный ON/OFF;
3. экран светомузыки + M01;
4. калибровка микрофона;
5. остальные музыкальные режимы;
6. будильник/RTC;
7. фон;
8. ночник;
9. сервисные функции и улучшение UX.

Таким образом приложение не блокирует запуск проекта: первый рабочий UI появляется сразу после минимального Wi‑Fi API.
